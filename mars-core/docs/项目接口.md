# MARS 项目接口（schema_version 2）

MARS 不包含任何领域代码。代码仓、数据、评测方法、检查脚本、领域说明和背景资料都放在用户的项目文件夹里，MARS 读取项目声明 `.mars/project.yaml` 并据此执行。完整可运行的例子见 [`examples/toy`](../examples/toy)。

## 1. 项目文件夹

```
我的项目/
├── .mars/
│   ├── project.yaml        # 项目声明（第 2 节）
│   └── pack/               # 本项目的评测、检查、诊断脚本与领域提示词；随项目走
├── context/                # 背景资料（.md / .txt）：Step1 调研、提案与决策读取
├── tasks/                  # 研究约定（第 4 节）
├── data/                   # 数据，或在 project.yaml 中引用外部路径
├── runs/                   # MARS 写入：每次运行的记录
└── workspace/              # MARS 写入：基线副本、候选分支、评测缓存
```

代码仓只读引用：MARS 在 `workspace/bindings/<绑定>/base` 建固定版本的副本，候选在其 worktree 分支里修改。项目文件夹可以整体移动。

## 2. project.yaml

```yaml
schema_version: 2
name: 示例：一维拟合
objective: 在特征个数不超过 4 的前提下降低验证误差
python: /path/to/python          # 可省略：本机 configs/machine.yaml 的 python，或运行 MARS 的解释器

repo:
  path: source                   # git 仓库（相对项目或绝对路径），只读
  ref: HEAD                      # ref 与 commit 至少一个
  editable_files: [model.py]     # 候选允许修改的文件（glob）；其余改动自动撤销
  context_files: [model.py, train.py]   # 可选：给模型阅读的基线代码
  required_files: []             # 可选：绑定时必须存在的文件
  setup_patch: .mars/pack/adapter.patch # 可选：建基线副本时打一次的补丁（git am 或 git apply）

datasets:                        # 名称只能用字母、数字、._-；数量不限；data 可以是文件或目录
  - {name: clean, data: data/clean.csv}
  - {name: noisy, data: data/noisy.csv, config: configs/noisy.yaml}   # config 可选，作为 {config} 传给命令

evaluate:                        # 一次评测 = 在候选副本里执行这个命令
  command: "{python} {pack}/evaluate.py --data {data} --steps {steps} --seed {seed} --output {output} --overrides {overrides}"
  timeout_seconds: 600
  max_parallel: 2

metrics:                         # 评测输出里的指标；门槛、筛选、报告只认这里的声明
  primary: val_mse               # 筛选时与多种子基线噪声底比较的主指标
  fields:
    val_mse: {label: 验证误差, unit: "", better: lower}
    params: {label: 参数个数, better: lower}

checks:                          # 可选：确定性检查（编码后每轮修复、训练前），输出 JSON，ok=false 即退回修复
  build: "{python} {pack}/check.py"
  # size: {command: "...", when: measure, timeout_seconds: 900}   # when: implement / measure / 两者（默认）

diagnostics:                     # 可选：提案可以申请的诊断
  # inspect: {command: "...", description: "基线输出的统计", source: baseline}   # source: baseline 在基线筛选输出上执行
  # weights: {command: "...", auto: true}                                 # auto: 每轮筛选后自动执行；输出含 tensors 时进化回放显示
  # steps_per_epoch: {command: "..."}                                     # 可选：输出 {"datasets": {名称: {steps_per_epoch, epochs}}}，步数输入框据此换算 epoch

editable_config_keys: [learning_rate]     # 可选：超参寻优和方案可以覆盖的配置键
search_space:                              # 可选：超参寻优的范围
  learning_rate: {type: float, low: 0.005, high: 0.2, log: true}

prompts:                                   # 可选：注入通用提示词的领域内容（项目内文件）
  domain: .mars/pack/prompts/domain.md     # 问题背景、模块说明（Step1 与决策）
  implement: .mars/pack/prompts/implement.md   # 编码规则（编码 Agent）
  decide: .mars/pack/prompts/decide.md     # 证据的领域解读（决策）
context_sources: [context]

remote:                                    # 可选：远程 GPU；SSH 连接在本机 configs/machine.yaml
  enabled: false
  name: gpu1
  data_path: /data/project                 # 或 {数据集名: 远程绝对路径}
```

项目声明不能包含 Key、密码或私钥字段。

### 命令占位符

| 占位符 | 含义 |
|---|---|
| `{python}` `{pack}` `{project}` `{workdir}` | 解释器、`.mars/pack` 目录、项目目录、本次的代码副本目录（命令的工作目录） |
| `{dataset}` `{data}` `{config}` | 数据集名称、数据路径、数据集的 config |
| `{steps}` `{seed}` | 预算（0 = 项目的完整预算）与随机种子 |
| `{output}` | 本次评测的输出目录：由评测命令自己创建（MARS 只建上级目录），图片等写在这里；诊断里是对应的筛选输出 |
| `{baseline}` | 1 = 基线，0 = 候选 |
| `{overrides}` | JSON 文件：本次的配置覆盖（超参寻优）或诊断参数 |

命令字符串按 shell 规则切分，但不经过 shell 执行；占位符在切分后替换，路径中的空格和中文不需要转义。

### 评测与检查的输出

评测命令最后一行 JSON：

```json
{"ok": true, "metrics": {"val_mse": 0.0004, "params": 3}, "curve": [[200, 0.01], [400, 0.004]], "info": {}}
```

失败时 `{"ok": false, "error": "原因"}`。缺少主指标视为失败。评测过程中可以在 `{output}/progress.json` 写 `{"step": 已完成步数, "total": 总步数, "epoch": 可选}`，算力页据此显示进度。auto 诊断输出 `{"tensors": [{"name", "shape", "effective_rank"}]}` 时，进化回放显示参数张量的变化。输出目录里的 `*.png` 会作为证据图保存到运行记录。检查和诊断同样输出一行 JSON，检查用 `ok` 表示是否通过，其余字段原样作为证据。

## 3. 本机配置 configs/machine.yaml（不进仓库）

```yaml
python: /usr/bin/python3
remote: {name: gpu1, host: 10.0.0.1, port: 22, user: me, key: ~/.ssh/mars_gpu, root: /home/me/mars, device: "cuda:0", max_parallel: 2}
```

远程执行：MARS 把候选提交推到远端、同步 `.mars/pack`，在远端用 `python3` 执行同一条评测命令（数据路径换成远程路径），再取回输出目录。

## 4. 研究约定（tasks/*.yaml）

```yaml
title: 示例：降低验证误差
objective: 在特征个数不超过 4 的前提下降低验证误差
constraints: [只修改 model.py 的 features(x)]
targets:
  gates:                                   # 完整验收：候选相对完整基线，worse_by ≤ max_worse（负数 = 要求更好）
    - {metric: val_mse, max_worse: 0.0}
  checks:                                  # 检查输出的门槛；字段路径可用 * 匹配所有键
    - {check: build, field: params, max: 4, stop: true}   # stop：不满足就不训练
budget:
  proposers: 3
  routes: 2
  research_sources: 6
  max_step1_rounds: 1
  max_iterations_per_route: 3
  repair_turns: 2
  codingagent_minutes: 10
  prequick: {dataset: clean, steps: 200, gates: [{metric: val_mse, max: 1.0}]}   # 可选：短预算绝对门槛
  screen: {steps: 500, seeds: [1, 2, 3], margin_floor: 0.0001}  # 主指标与多种子基线中位数比较，噪声门槛 max(margin_floor, 2×MAD)
  verify: {steps: 2000, seed: 1, window: 0.0}                     # window：筛选差距在此范围内也做完整验收
human_approval: true
execution: {environment: local}
```

`worse_by` 按指标方向计算：越低越好时为 候选 − 基线，越高越好时为 基线 − 候选；负数表示候选更好。

## 5. Step2 每轮流程

1. 编码 Agent 在候选分支修改允许的文件；每轮修复后执行范围检查与 `checks`（implement）。
2. 提交后执行 `checks`（measure）与 `targets.checks` 门槛；`stop` 门槛不满足则本轮止于 checks。
3. 执行方案申请的 `diagnostics`。
4. 可选 prequick：短预算评测与绝对门槛。
5. 筛选：每个数据集评测一次，主指标与多种子基线比较；之后执行 `auto` 诊断。
6. 筛选通过（或在 window 内）且检查门槛全部通过时，做完整预算验收，按 `targets.gates` 判断。
7. 强模型依据证据判断机制并给出下一轮改动。

## 6. 旧版项目

schema_version 1（旧版内核）的运行仍可在工作台查看，但不能续跑；评测缓存不复用。旧项目需要按本文件改写 `.mars/project.yaml`，并把领域脚本放进 `.mars/pack/`。
