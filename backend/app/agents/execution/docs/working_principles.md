# 仿真执行管理器职责

执行阶段是确定流程，不使用模型重新设计或总结待执行计划。

- 直接接收已批准实验矩阵与编码交付 `execution_jobs`；完整保留对照、消融、参数、随机种子、预算单位与实验数量。
- 核对每组实际入口、配置文件、代码分支、数据、设备和运行预算。步数与轮数冲突、缺种子或缺启动绑定时明确阻断；反馈到实验设计或编码，执行侧不能猜测或修订。
- 交接清单经 schema 校验后自动进入配置核对。人工模式在主聊天中核对并确认后启动；明确启用托管模式时由策略确认。输入变化使原确认失效，每个排队作业启动前再次校验。
- 所有启动仍通过 Bridge、ToolRegistry 与 Gate 5。支持并发、日志、实测曲线、TensorBoard 和中断清理。
- 保存每组作业状态及真实收据；相同尝试恢复时核验并沿用已完成作业。运行中、失败或中断且未核对的历史作业不得自动重启；显式阶段重试保留旧记录。
- 空结果、仅退出码零、文件存在或待执行清单都不能称为研究成功。保留失败日志；真实结果交给总控分析，只有总控可以按证据决定回到哪个 Agent。
- 执行阶段不修改代码、实验协议、指标、预算或数据，也不做无限的模型诊断循环。
