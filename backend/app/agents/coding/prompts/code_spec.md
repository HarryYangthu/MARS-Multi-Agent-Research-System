# Code Spec Prompt

将当前项目已批准的 experiment plan 落成可审核的真实代码改动，产出 `code_spec.v1`（YAML frontmatter + Markdown body）。先阅读项目合同、项目规则、基线接口及要修改的真实文件。

## 输出重点

- `files_changed` 逐文件列出实际落地的改动。允许范围、保护路径、接口、数据 shape/dtype 和依赖限制来自本项目；缺少必要信息时明确阻断写入，不假设其他项目的类名、函数签名或张量结构。
- 文件清单以本任务成功写入的净差异为准，不能把已有文件的相同内容重写列为 added/modified。全部复用时填写 `files_changed: []`，正文说明复用文件、内容指纹与真实检查。重试会核对整个任务的写入链；先前已新增且本轮未变化的文件仍属于本任务的净新增。不要为登记制造无意义的修改。
- `implementation_plan` 连接已批准实验参数与真正消费它们的代码。不要添加无人读取的配置，也不要修改受保护的基线、数据划分或评测器以制造达标。
- 修改使用受治理的代码工具；ToolRegistry 权限与 Gate 5 必须保留。仅有建议或 diff 不等于代码已落地，必须引用实际工具结果并检查最终 diff。
- `baseline_compat` 如实说明保护范围和接口兼容证据。适合时采用独立模块或显式开关保留对照，但不把某一项目的实现方式写成所有项目的要求。
- `tests` 采用本项目真实检查命令，验证接口、shape/dtype、有限输出和指标计算口径。不能把“模型一定改善”或“所有 seed 一定达标”当作代码正确性断言；尚未执行的测试标记 `skipped`，失败保留原始证据。
- `patch diff` 应最小、可审查、可回滚；涉及 tensor 操作时标注 shape。`new_dependencies` 说明理由，`rollback_notes` 给出恢复方法。
- 示意代码和带省略号的 diff 只用于解释，不可执行。交付可执行补丁时必须带完整 `---`/`+++` 文件头和有效 `@@` 行号；已完成写入不需要再次应用补丁。

- `execution_jobs` 是机器可读的执行交付，每项 `name` 必须对应实验矩阵，`config` 只补充实际入口 `entrypoint`、`config_path` 或宿主登记的 `command_id` 等运行绑定。保留批准参数；明确随机种子、`max_iters` 和 `budget_unit`（steps/epochs），不得把步数换成轮数。每个配置必须存在且被真实代码消费。执行侧直接消费此清单，不再调用模型猜测命令。
- `entrypoint` 只填写脚本路径，不得填完整命令（例如 `train_static.py`，不能填 `python train_static.py --cfg ...`）；`config_path` 只填写配置路径。完整可读命令放在正文，预算与种子使用各自字段；以接入执行器的实际合同为准。

## 仿真过程与可视化交付

需要仿真的任务默认记录 TensorBoard 过程日志。宿主提供 `MARS_TENSORBOARD_ENABLED=1`，不得将仅包含最终指标的单点事件当作完整训练日志。接入当前代码仓已有的可视化函数，保存本次实际生成的频谱、通道比较、损失/验证曲线、系数热图、非线性特性与参数分布；按模型实际能力提供，不生成虚构图像。所有输出放在本作业目录，使用当前方案的种子、数据、评测口径及训练预算。

每个模型/候选拥有独立事件目录。记录优化器更新对应的 loss、学习率、验证性能及实际采集的参数快照，最终测试结果保持单次评测，不能为画曲线反复评测测试集。保存 JSON/CSV 作为原始证据，全部本次图像可通过 TensorBoard Images 展示。启动后验证事件确实写出，交付说明已支持的视图与没有采集的内容；缺依赖或缺过程日志明确报告。

## 反馈边界

只针对证据支持的代码问题修复。指标不达标可能源于假设、数据、协议或实现；不能默认归因为代码，也不能为了通过验收改写指标方向、阈值或测试集。迭代与目标服从任务合同和审批。
# 执行交接验收

有批准实验方案时，`experiment_plan_sha256` 必须绑定完整批准实验 Markdown（包含 frontmatter 和正文）的 SHA-256，`execution_jobs` 名称与矩阵一致。任务未安排实验设计时，不需要补写实验方案或捏造方案哈希；按用户目标、实际代码和配置交付完整 `execution_jobs`。纯编码任务不要求仿真清单，需要后续执行的任务必须交付实际入口/配置文件或登记命令、明确的 seed、预算数值和单位。实际种子和预算必须落实到入口；steps 不是 epochs，不能互相替代。当前入口不支持预算时先实现正确入口，不能提交另一套实验条件。缺项返回编码交付补齐，不能等到启动仿真才报错。配置文件和入口会由宿主再次核对；人审通过也不能跳过此验收。
