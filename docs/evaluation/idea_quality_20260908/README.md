# Idea 调研质量真实验证 · 2026-09-08

本轮目标：论文确实影响方法选择，选文原则、逐篇理由和提取思路可追溯；同一方案同时输出结构化交接与中文说明。来源/结构、模型审查、独立离线复核、真实实验是分别记录的状态。

## 固定任务与执行边界

公开符号任务为二维实标量 LUT：输入域 `[-1,1]^2`，保留固定均匀 `16×16` 双线性基线的 256 个可训练实参数；候选不得超过该预算。局部高曲率仅是假设，要求自主选文、读方法页段、给出至少两篇实际支持方法取舍的论文和完整判别实验。

使用真实 DeepSeek 请求、真实 OpenAlex/arXiv 检索及 PDF 阅读；无 Mock、固定 Agent 答案或预先注入论文。每次运行从已提交的干净源码启动，保留全部成功与失败子任务。入口为 `scripts/run_idea_research_live.py`，属于开发时直接调用 Idea 的验证；未声称工作台端到端成功，未批准方案或执行下游仿真。

## 失败如何指导修复

第十次自主检索到 10 篇不同论文，下载两篇完整 PDF 并读取 4 个页段窗口。子任务的独立 Reflection 实际拦截了不完整节点预算和有限尺度观察外推到渐近率的问题，修订后计数为 225+13+13=251；但另外的 Codex 复核发现，报告摘要及其中一项 finding 仍把多部件模型的整体比较归因为可训练节点本身。主方案的正则化消融起初未链接到含正则项的目标，修订后已修正，但最后未接受候选仍有联合节点约束定义缺口及手写正则导数错误。冻结节点导致参数减少本身是有效消融，模型审查要求用无效参数凑齐预算的建议也被单独识别为审查错误，未视为正确修复要求。此次 20 请求收到 19 响应，522,249 token 是已知下界；最后一次审查在 1200 秒总时限处中断，不补发结果，也不为原运行增加预算。原始报告、候选和事件记录均保留。

1. 第一轮之后，在真实验证配置中增加已实现的 arXiv 检索通道；明确委派围绕具体缺口、可分别只需一篇材料，不反复查询空知识库或限流服务。仍要求真实搜索与阅读收据。
2. 第二轮候选 `0ee9579ee8d41c3064a93b732f8867502514bb8366dac58a7ffc1cc11211505e` 自动通过，但独立 Codex 复核发现：两个消融等价、边界消融对定义域内输入无作用、论文链接的备选有尺寸矛盾且缺公式、初始化额外标签未纳入共同数据预算、14 列配置缺规范评估记录（其 237 参数未超预算）。保留原始接受记录及另行生成的 `manual_quality_review.json`，没有改写成“自动拒绝”。审查随后补齐写作阶段的完整任务要求，并提高推理强度。
3. 第三轮未能进入模型审查：667 字调用说明被 512 字截断，完整性保护据此认定缺少必需记录。修复为完整保留所需 Observation，审查阶段也不再扣除没有发送的工具定义所占空间。以原失败记录和完整任务重放装载，全部必需记录完整、估算占用 78,346 / 96,000；这是组件复核，没有调用模型或补发接受证明。
4. 第三轮研究报告另有可追溯但不正确的理解：SIREN 的“二阶导数为零”误写成“导数为零”，带偏置 `2→n→n→1` 的参数计数漏项。原文支持与算术复核说明：引句存在只证明出处，不能代替语义审查。
5. 引句不匹配时，校验反馈补充同一实际可见页内不超过 300 字符的连续原文定位片段；不自动替换引句或推导结论，候选仍无效，须由研究 Agent 修订并重新校验。已以第三轮真实失败子任务确认错误仍在、片段确实来自同页、原始 checkpoint 未修改。
6. 第四轮实际经历引句拒绝、收到原页定位提示、模型修订并通过来源核验。审查也实际收到完整必需记录，占用估算 63,276 / 96,000，没有遗漏；但 16,384 输出 token 全部消耗于思考，最终 JSON 为空。随后将正式 Idea 和验证配置的输出上限调至 32,768、单次调用时间调至 360 秒；验证配置增加有限修订余量（14 次模型调用、4 次协议/校验修复、3 次审查），并提示精简可见分析、保留具体方法定义。此配置变更不修改先前运行的预算或结果。
7. 第五轮保留了 21 次实际研究工具连接失败。独立只读探测确认：继承本机代理时 arXiv/OpenAlex 超时、GitHub TLS 失败；对相同研究服务及 GitHub 的进程内直连探测返回 200。网络诊断单独归档，不修改原运行结果、不把探测论文注入模型。后续运行仅为研究服务设置进程级直连，不改变系统代理。
8. 入口复核发现工作台默认提交尚未接入的 `auto` 模式。现将默认值设为正式可用的 `fast`，禁用未开放选项；API 在创建运行前明确拒绝 `auto/deep`，省略字段仍保留 Agent 默认值。历史运行读取兼容保持不变。
9. 第六轮主模型生成约 66 KB 的说明文字后提交了无效 JSON；修复时整份响应被重复编码、当作不可缩减上下文，超过输入预算。现仅对带原生工具调用的响应缩短重复说明，并显式保留长度、摘要和截断标记；原始工具参数、现有候选、未解决问题及审查正文保持完整，不自动修复或执行错误调用。以该轮实际任务、失败输出和工具记录回放，旧处理可复现超限，新处理保留全部历史及原始参数并装入预算；这不是模型重跑或补发接受证明。
10. 第六轮成功研究报告的离线复核发现，摘要将第一篇的一维 L2 节点密度规则和渐近投影比例错说成两篇共同结论；第二篇实际讨论凸/凹一维 L∞ 断点误差均衡。独立记录保留了这一错误，未把不存在的最终候选判为通过或失败。
11. 第七轮论文阅读和一次高强度审查实际完成。主候选正确把 15×15 的 253 个可训练量分为 225 个节点值与 28 个间距 logits，但审查要求补齐多场景和消融的独立训练定义；模型新增具名臂时又被仅允许 `baseline/candidate` 的结构拒绝，不同架构的参数计数也被要求复用主公式。随后新增显式比较组及完整候选参数账本覆盖；旧两臂/同架构尺寸配置保持兼容，数据隔离和预算检查继续作用于每组。该结构扩展不自动修复或接受原候选。
12. 第八轮实际遇到重复 JSON 字段，新的修复上下文保留全部原始参数并发出下一次模型请求，总输入上界 94,981 / 96,000；只省略早期空知识查询的完整正文，保留行动索引与成功研究报告。随后连接因休眠中断，不能据此认定修复后的方案通过。该轮研究报告另有两项过度推断：离线 SVD 需要完整矩阵，不等于低秩因子不能端到端训练；QTT 位序重排也不必改变插值语义。独立语义复核保留了这些问题。

## 已验证的交付接口

第二轮的不可变交付包包含 `proposal.md`、`proposal.json`、`summary.txt`、`research_brief.md`、`research_evidence.json` 与 `acceptance.json`。实际文件内容、候选摘要、引用身份和可信研究报告重验通过；调用证据装配组件能为该候选生成 `idea.research_handoff.v1`。没有创建人工批准记录或启动 Experiment Agent。这一组件结果不能抵消离线发现的方案缺陷。

`research_brief.md` 按已接受字段展示任务、原则、每篇论文的取舍、原文页码、提取思路、迁移条件、具体方法位置和未决问题。`proposal.json` 与规范 Markdown 指向同一候选，包含 `idea.handoff.v1`、完整方法及 `research_assessment`，下游批准路径会重新核验证据。
