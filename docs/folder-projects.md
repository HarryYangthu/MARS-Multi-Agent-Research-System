# 文件夹项目与自动上下文

在工作台顶部点击“新建项目”，选择保存位置和项目名称。系统会创建同名文件夹；已有研究代码则使用“打开文件夹”。再次打开同一个文件夹会回到原项目，项目名称相同的两个文件夹仍是独立项目。

```text
研究项目/
├── AGENTS.md             # 项目约定、术语、约束、需要保留的接口
├── README.md             # 研究目的和总体说明
├── context/
│   ├── background.md     # 背景、公式、关键代码解释
│   └── prior-work.md     # 已有研究结果与经验
├── src/                  # 实际代码，可以沿用现有目录结构
└── .mars/
    ├── project.yaml      # 稳定项目身份与上下文文件规则
    └── repo_link.yaml    # 指向当前文件夹的代码工具配置
```

首次打开已有文件夹只添加 `.mars/` 中缺失的配置，不覆盖现有背景、项目约定或代码。新建项目会额外提供 README、AGENTS 和空的 context 目录。已有 PIMC 项目及其历史任务仍然可选。

## 自动加载

默认加载根目录 `AGENTS.md`、`README.md` 和 `context/**/*.md`。生成方案与独立评审使用同一份项目背景；AGENTS 是项目约定，其他文档作为参考资料。代码工具指向当前文件夹，按需读取相关代码。不会把整个代码仓或 PDF 自动塞入提示词。

主控对话也会在组织新消息时读取当前项目背景。创建研究任务后，该任务中的 Agent 使用下面描述的冻结快照。

“项目资料”和“新建研究任务”页面可查看文档列表、长度及全文预览；修改文件后点击“重新扫描”。需要增加其他 Markdown 路径时，可编辑 `.mars/project.yaml` 的 `context_files` 列表。路径只能位于项目内，隐藏目录、隐藏文件及越界链接不会加载。

默认上限为 100 份文档、总计 120,000 字符。超过限制时会明确提示，不能创建任务，不会默默截断。需要时可调整 `MARS_FOLDER_CONTEXT_MAX_FILES` 和 `MARS_FOLDER_CONTEXT_MAX_CHARS` 并重启服务；实际可用长度仍受所选模型的上下文窗口限制。

## 任务快照

点击创建任务时，系统把完整背景保存为该任务的 `input/folder_context.v1.json`，含逐文件内容、路径和校验摘要。后续启动、评审或恢复同一任务继续使用这份快照。修改背景文件只影响新任务，已有任务不会悄悄改用新资料。

Idea Agent 工作区的“调研资料”可查看这份背景快照，以及实际调研和代码阅读留下的材料。快照形成于任务创建，不代表模型已经完成调研或科学验证。

任务记录继续存放在 MARS 的 `runs/` 中，页面按项目身份筛选。项目登记保存在本机的 `workspace/folder_projects.json`，不会提交到 Git。文件夹移动后，重新打开新位置即可更新登记并保留项目身份；复制出一个独立项目时，应移除副本的 `.mars/project.yaml` 再打开，以避免共享身份。

文件夹路径指向运行 MARS 后端的机器。本地部署时即当前电脑；这一版不上传整个目录，也不自动迁移旧项目。
