# 公司电脑更新与模型切换

在原有 `D:\Code\新建文件夹\MARS-Product` 文件夹中更新。使用本次核心更新 ZIP，不用重新安装依赖，也不用搬迁项目。

1. 将核心更新 ZIP 保存在公司电脑上，把它拖到原文件夹中的 `Update-MARS.cmd`。不要直接解压覆盖整个目录。更新器会检查兼容性、备份旧代码、更新核心文件并启动检查；失败会回退。
2. 启动后打开原有项目。对话输入区的“对话模型”可选择已经保存的模型；点“配置自定义模型”新增连接。显示名称可自由填写，模型 ID 必须使用公司网关实际登记的名称。
3. 千问部署选择“千问 · 200k”，Gemma 部署选择“Gemma · 160k”。填写实际接口地址、API Key 和部署上下文长度。配置全系统共用，其他项目可直接选择；每个对话记住自己的选择，后续新对话沿用最近选择。
4. 发送一个小任务验证，例如：`运行已有五层模型，完整训练2个epoch，固定seed=2026；仿真完成后暂停。` 确认页面出现真实训练进度、指标和 TensorBoard 后再增加训练预算。

模型选择仅影响后续的主控对话请求。后台各阶段仍使用设置中的 Agent 模型配置，已启动任务不会被换模型、取消或重建。处理中不能切换；等本轮结束或中断后再选。

## 每次保留的内容

- `dependencies/`：Windows Python、Node、Git 和离线依赖。
- `local/`：本机环境、已保存模型、凭据和更新备份。
- `workspace/`：项目、代码、数据、对话、运行记录。
- 已有 `configs/` 和 `.env` 配置：更新器只补缺失项，不覆盖公司连接、密钥和执行设置。

模型资料保存在系统 `local/model_profiles.json`，密钥另存 `local/model_profile_secrets.json`。它们不属于核心源码，不应上传 GitHub。更新后仍然保留。

## 慢模型与恢复

主控使用较小工作集，历史和长背景按需回读；部署的 200k/160k 容量不意味着每次都发送全部材料。明确工具、参数与真实回执由 MARS 执行和核对，减少依赖模型自行检查格式和重复阅读。

中断后的模型请求不会自动重发原请求，未知用量和原预算保留；已经完成的工具回执可以恢复。未取得回执的修改不会重复执行，先核对已有任务。重新打开对话后可发“继续”，原有任务按实际检查点恢复或重试。

本地测试和公司验收分开：源码、协议解析、真实文件恢复和本地真实模型测试不代表公司网关已经通过。公司端若失败，保留页面里的具体错误和调用记录即可继续定位。
