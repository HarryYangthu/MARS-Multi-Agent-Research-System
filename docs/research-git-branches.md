# 在原仓库中开展研究

项目接入本地 Git 仓库后，编码阶段在原目录创建并切换到 `mars/<任务标识>-<摘要>` 分支，不克隆仓库、不创建实验副本或 worktree。分支起点为当前已提交的代码，原分支及提交保留。

每个任务的分支、原分支、原提交和代码目录保存在 `runs/<任务>/input/research_branch.json`。重试和恢复复用记录，不重新生成分支。编码和执行阶段持有仓库锁，同一工作区不能同时运行两个代码阶段。

项目的 `repo_link.yaml` 仍保留基线只读配置。可写权限只在宿主绑定本任务分支期间有效，允许路径、受保护路径及工具审核继续生效。工具不能修改 Git 控制文件或凭据，也不能通过传入其他目录绕开绑定。

第一次进入编码时，仓库必须已有提交、处于分支上且没有未提交的改动。系统不自动初始化 Git、暂存用户改动、强制切换、拉取远程或重置。若未满足条件，先在本地保存已有工作，再重试阶段。无 Git 的显式可写工程保持原来的接入方式；只读且无 Git 的工程需要先建立版本历史。

代码产物经过人工审核后，执行阶段仅提交审核文档中列出的实际改动，生成本地实验检查点，再运行实验。额外未审核的改动会阻断提交。检查点不会推送或合并到原分支。中断和失败保留分支与未完成改动。

此逻辑用于现有项目流程。已有冻结研究合约的任务继续遵守其已封存的源码边界，不能用分支授权绕过合约。

## 验证

`backend/tests/unit/test_research_git_branch.py` 使用真实临时 Git 仓库及真实代码工具，验证补丁写入、回滚、编译、原分支保留、脏工作区阻断、分支复用、并发锁、分支切换后的权限失效、路径保护、符号链接阻断，以及审核后提交。
