# 在原仓库中开展研究

项目接入本地 Git 仓库后，编码阶段在接入目录创建并切换到 `mars/<任务标识>-<摘要>` 分支，不再拉取额外分支、不克隆仓库或创建 worktree。每个任务只建立一个分支，重试、返工和恢复继续使用它。首次起点为已提交基线；从另一任务切换时，使用该任务记录的原基线，不继承它的实验改动。原分支及提交保留。

每个任务的分支、原分支、原提交和代码目录保存在 `runs/<任务>/input/research_branch.json`。重试和恢复复用记录，不重新生成分支。编码和执行阶段持有仓库锁，同一工作区不能同时运行两个代码阶段。

项目的 `repo_link.yaml` 仍保留基线只读配置。可写权限只在MARS绑定本任务分支期间有效，允许路径、受保护路径及工具审核继续生效。工具不能修改 Git 控制文件或凭据，也不能通过传入其他目录绕开绑定。

第一次进入编码时，仓库必须已有提交、处于分支上。MARS在 Git 公共目录保存分支归属索引，在任务的 `input/research_changes.json` 保存各次受治理写入后的文件指纹。编码完成、停止或失败时，匹配指纹的改动自动提交到本任务分支；新增、修改、删除和回滚均有记录。无实际变化不生成空提交。突然退出后，下次进入该任务或切换到另一任务时继续保存已记录的改动。只读状态查询不创建分支或提交。

自动提交只是保存，不是审批。执行前仍核对从基线到当前候选的全部改动是否属于已批准代码方案，已提交的代码也不能绕过此检查。检查点不推送或合并到基线。未记录的用户文件、外部覆盖后的内容、凭据和其他任务改动不纳入自动提交；遇到这些文件会保留原内容并说明原因。系统不会自动暂存、重置或丢弃用户工作。无 Git 的显式可写工程保持原来的接入方式。

本地代码读取允许重新执行，以读取写入后的真实文件；写入、网络工具和需要审批的操作仍按原规则防止重复执行。已停止的编码任务只有显式指定重新执行、清理完成、Git 分支与任务身份匹配，且没有未确认工具或模型请求时，才允许在原任务新建调用重试。启动或重启服务不会自动恢复已停止任务。

此逻辑用于现有项目流程。已有冻结研究合约的任务继续遵守其已封存的源码边界，不能用分支授权绕过合约。

## 验证

`backend/tests/unit/test_research_git_branch.py` 使用真实临时 Git 仓库及真实代码工具，验证正常和中断保存、原分支保留、固定分支重试、跨任务基线隔离、进程退出恢复、路径保护、用户暂存文件隔离、新增/删除/回滚，以及自动提交后仍需审批。
