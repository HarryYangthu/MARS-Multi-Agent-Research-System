## 真实任务验收口径

`scripts/run_runtime_e2e.py` 经正常 API 驱动 Idea → Experiment → Coding → Execution → Writing。
工程任务使用真实 CPU 多项式岭回归：固定原始基线与 11 个数值样本，seed 0，8 个训练样本与 3 个保留样本，训练集内计算归一化参数。
候选初始与基线完全相同，Agent 只能改 `candidate.py` 的阶数与正则系数。实际外部进程执行两次拟合，产生绑定请求身份的指标、测量文件与收据。

这能检验工程执行闭环，不能替代真实 PIMC 数据、科学创新性、独立测试集或跨任务稳定性证明。模型可读取本工程任务的全部样本，故其保留样本误差不应被解释为研究中的盲测泛化性能。

## 本轮实跑暴露并修复的问题

1. 上传数据返回 `sha256:` 前缀，驱动用裸摘要比较，导致误拒绝。现在按 API 契约核对算法标识、摘要和项目。
2. Execution Agent 曾返回固定 PIM 计划。现在由真实模型读取已批准方案生成计划，Schema 禁止在计划阶段填入测量指标或声称完成；实际执行工具仅由宿主启动。
3. 调度器曾忽略显式随机种子。现在保留合法整数，包括 0；非法值明确失败。
4. Coding 曾只要求返回补丁。现在必须通过真实工具落实变更，缺成功写入观察不能通过验收。
5. 宿主批处理回调返回值不符合工具输出 Schema。现在返回真实后端、run 身份、并发、结果和失败列表。
6. 批处理中有失败时曾可能继续完成节点。现在持久化实际失败证据后抛出错误，阻断后续完成。
7. 下游默认上下文容量偏小；现在显式配置预算保留完整交接。无实际 loss 曲线时不生成空白的 PIM 曲线图。
8. 通用 Agent 将无 message 的原始循环事件直接交给界面适配器，导致 Experiment 在模型调用前失败。现统一转换事件并隔离通知失败；已通过正常重试入口继续完成原 run。
9. 知识查询工具未声明必需参数，使模型先发空请求再修复。已补齐共享查询 Schema，并将工具说明改为适用当前项目的描述。
10. 诊断层曾将缺少规则误判为通过。现在明确区分未评估与通过；缺失、非有限或部分行缺失的测量值不能通过，也不伪装成观测值 0。
11. 工程夹具现在提供真实语法、参数约束与受保护输入完整性检查，并预先配置正改进的诊断规则；代码检查不冒充实际实验。
12. 报告模板曾包含未发生的辩论轮次与示例意见，触发真实报告审查拒绝。默认模板改为 0 轮、空意见，只能依据实际凭据填写。
13. 工程夹具曾将诊断规则写入仓根目录，但文件夹项目从 `.mars/diagnostics.yaml` 加载规则，导致真实运行显示未评估。现按项目元数据契约写入；集成检查直接调用运行时配置加载器验证阈值与循环上限。
