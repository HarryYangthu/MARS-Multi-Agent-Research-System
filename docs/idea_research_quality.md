# Idea 调研质量与双重交付

目标是交付有来源依据、解释清楚、可交给实验环节验证的方案。成功调用工具、下载论文、字段非空，都不足以证明调研有用。

## 从研究问题到方法决定

当前正式委派调研提交包含 `research_assessment`（版本 `idea.research_assessment.v1`）：

| 字段 | 要回答的问题 |
|---|---|
| `task_question` | 本次要解决什么具体问题？ |
| `selection_principles[].criterion / task_basis` | 按什么原则选文，这条原则对应哪个任务约束或信息缺口？ |
| `source_decisions[].decision` | 对已取得可用研究结论的每篇文章，最终采纳、排除还是暂缓？ |
| `reason / task_relevance / criterion_ids` | 为什么作此决定，与当前任务、选文原则有什么关系？ |
| `insight_ids / transfer_assumptions` | 采纳哪些思路，迁移成立需要哪些条件？ |
| `stopping_reason / remaining_gaps` | 为什么足以形成当前方案，还缺什么？ |

`research_links` 将真实委派报告中的思路连接到 `method_spec` 的具体定义，并记录迁移理由。报告保留原文引句、页码、阅读收据、文档摘要、论文结论、迁移推断和局限；宿主从实际工具记录重验这些来源。

仅因关键词相同、引用量高或容易下载，不能据此认定论文有用。可以采用相邻领域的方法，但必须说明任务机制的对应关系、成立条件及不能直接迁移的结论。否定性结论也可以支持一个真实的方法取舍；不能添加无实际作用的字段凑篇数。

每个委派围绕一个具体信息缺口设置所需材料，总篇数在主 Agent 汇总时计算。论文不必已经解决完整目标任务；要证明具体机制为何可以迁移，并将适配成本计入方案。检索服务限流时切换已开放的来源，不把反复换关键词当成补救；空知识库不应重复占用阅读预算。真实验证配置同时开放 OpenAlex 和 arXiv，备用通道仍须留下真实检索与阅读记录。

## 验收分层

1. **来源与结构**：核对真实阅读收据及文档摘要、论文与思路身份、原则引用、逐篇决定覆盖、思路到方法的有效引用。采纳集合必须与实际方法链接一致，排除或暂缓文章不得同时用作方法依据。新合同的最低来源数只统计实际链接的不同论文；同论文不同版本或重复委派不会增加篇数。
2. **独立上下文模型审查**：检查文章与任务是否相关、节选是否支持结论、迁移条件是否合理、是否存在装饰性引用，以及中文概括是否与规范方法一致。审查收到与写作相同的完整任务和宿主要求，并检查相同消融、域内无效改动、遗漏评估尺寸及初始化额外标签。默认 Idea 开启高推理强度的 Reflection；要求研究档案却关闭审查的配置在调用模型前明确失败。
3. **实验验证**：尚未发生。结构检查和模型审查均不能证明方法有效、新颖或理解一定正确；这些结论需要下游实验和必要的人工评审。

审查必需的真实工具记录按完整内容装载，保留原文页段及调用说明，不用截短内容或仅含地址的索引代替。若完整材料与任务、候选一起超过容量，则在调用审查模型前失败。审查没有工具调用权限，因此不为未发送的工具定义预留容量。

模型的思考与可见输出共用输出上限。正式 Idea 预留 32,768 输出 token 和 360 秒单次请求时间；耗尽上限不是审查通过，仍必须在有限修复预算内返回完整结构化判断。

检索命中、下载文件、读到页段、有可追溯提取、实际用于方案，是不同数量。`research_brief.md` 只统计成功报告中的引用页段来源及方案实际使用来源；完整检索和失败委派的数量另见运行记录。页段阅读不能称为全文阅读。材料不足应保留缺口并失败或修订，不应用无关论文补足门槛。

## 一次接受，两种表达

每个接受版本有独立交付目录，不覆盖先前版本：

| 文件 | 用途 |
|---|---|
| `proposal.md` / `proposal.json` | 相同规范方案的 Markdown/frontmatter 与完整结构化元数据；包含方法、判别规则、交接要求、调研决定和研究链接 |
| `summary.txt` | 一两句中文说明，概括做什么及预期作用；不得把假设写成实测提升 |
| `research_brief.md` | 面向人的问题、原则、逐篇理由、引用页段、提取与迁移、方法位置及未决问题 |
| `research_evidence.json` | 与提案摘要绑定的可信委派报告，保留原结论和使用限制 |
| `acceptance.json` | 分开记录结构检查、研究决定一致性、模型审查和实验状态 |

简短正文与 `human_summary` 保持一致，完整方法仅以规范元数据为准，防止维护两份互相冲突的方法定义。中文研究说明由已接受字段和可信报告渲染，不另让模型补写无法追溯的结论。

下游仍以批准后的方案为输入。包含新版调研决定的批准方案会附带 `idea.research_handoff.v1` 上下文包，携带重新核对过来源的研究证据；批准或手工修改不被当成原候选已通过模型审查的证明。未提供真实基线和数据时，交接必须将这些列为执行前提。

## 历史兼容与验证边界

历史 `proposal.v1` 保持可读。离线审计只有在当前候选摘要对应的验证记录声明 `research_assessment_required=true` 时，才要求新版决定和双重交付文件；不会用新规则给旧运行补发质量证明。

自动测试使用纯合同输入、真实临时文件和真实配置。它们验证身份、链接、数量、文本一致性及失败边界，不用模型或工具替身宣称一次研究成功。真实论文验证通过 `scripts/run_idea_research_live.py` 另行执行，记录实际来源和全部委派消耗；该脚本属于开发时直接调用 Idea 的入口，不能据此声称工作台端到端验收或真实项目仿真已完成。
