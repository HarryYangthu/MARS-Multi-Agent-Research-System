# Agent 额度策略与本次排障记录

`configs/model_usage.yaml` 统一控制整个部署，包含已有任务：

```yaml
token_usage_mode: statistics_only
agent_quota_mode: statistics_only
```

`agent_quota_mode: statistics_only` 表示持续计量，不因模型/工具调用次数、累计 token、累计费用、累计活动时长、评审轮数、研究委派次数或 Discovery 累计额度而停止。`limited` 恢复原配置约束。运维可用 `MARS_AGENT_QUOTA_MODE` 覆盖，测试有限模式可设为 `limited`。修改后重启后端生效；失败任务通过正式重试入口生成新调用，不能直接篡改旧检查点。

历史账本、失败记录、配置哈希及未知用量的保守记录原样保留，新调用记录实际采用的额度模式。恢复入口与执行确认读取同一模式，防止运行器已经解除限额、页面仍阻止重试。返回的有效调用余额为 `null` 时表示不限，不表示零。

| 已见问题 | 原因 | 修复 |
| --- | --- | --- |
| 研究、评审和编码输出多次截断 | 各角色与运行配置分散，原输出 8192 | 所有角色单次输出统一提高到 32768；截断响应明确失败，保留真实用量，禁止执行残缺工具参数 |
| 编码未完成就停止 | ZCode 独立设置 24 次模型、40 次工具、900 秒上限，覆盖了 Agent 完成驱动模式 | 统计模式同时覆盖 ZCode 和原生循环；每次工具返回展示有效余额 |
| 页面提示已计入 100/100、还需预留 3 次 | 全任务账本累计计入历史调用与网络重试；只改 Agent 参数无效 | 统计模式同时用于真实请求准入、恢复判断与执行确认；旧用量不清零 |
| 分阶段修复后再次遇到其他额度 | 委派、Discovery、冻结研究合同各自另有累计预算 | 使用统一统计模式，保留账本身份与每次操作证据 |

仍保留服务本身的上下文/单次输出容量、单次请求超时、有限网络重试、并发容量、单个训练进程的超时、重复相同错误检测、未知操作核对和结果校验。这些检查不能伪装为任务成功；无效提交会返回实际错误。训练步数是实验参数，不是 Agent 调用额度，不随此开关改变。

此改动不批准任何研究内容，不改变 `review_mode`。用户开启主控托管时，由系统主控按既有流程审查；修复者不代替主控审批。

验证：真实本地文件/SQLite 账本的超额准入与历史记录保留、原有限模式回归、重复错误检测、真实 ZCode MCP/进程边界及静态类型检查。完整科研成功仍须以真实训练、测量及最终报告证据为准。
