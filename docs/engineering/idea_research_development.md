# Idea 论文研究能力开发与验收计划

目标：研究任务进入正式 Idea Agent 后，能按信息缺口委派独立上下文的研究子 Agent，真实检索、读取并提取论文方法，再产出可验证的方案与一两句人话总结。Schema 合格、模型审查、真实仿真分开报告。

| 工作 | 实现责任 | 验收证据 |
|---|---|---|
| 研究凭据与契约 | 研究工具/证据实现 Agent | 来源身份、文件哈希、真实读取页段、摘录匹配、思路与局限 |
| 独立研究子 Agent | 编排实现 Agent | 独立配置/上下文/trace；仅研究工具；有界委派且失败保留 |
| 正式 Idea 接线 | 主开发 Agent | 默认 fast 入口可委派；研究思路关联到实际 method_spec；交付与独立审查 |
| 回归与真实测试 | 测试实现 Agent | 纯函数及真实文件回归、实际 DeepSeek＋arXiv/PDF 工具运行、所有父子成本与失败记录 |

阶段一：检查已有实现与缺口，确认工具、schema、预算和保存路径。已有单 Agent 能检索并读取 PDF，但此前五角色组件测试不包含论文研究。

阶段二：并行实现研究契约/凭据、独立研究 Agent 和编排、正式交付引用；合并前核对接口。程序验证来源、哈希、摘录存在及字段引用；模型独立审查提取和迁移是否合理。可见文本并不证明理解或全文阅读。

阶段三：增加拒绝伪造引用、错误页码、篡改文件、未知思路、无方法字段、未配置服务、预算耗尽的回归。禁止 provider/工具替身或固定成功答案。

阶段四：使用公开符号任务从干净已提交源码运行真实端到端 Idea 测试。没有预置论文名、链接或方法答案；基线明确为已使用双线性插值的 16×16 实标量 LUT，候选预算≤256。无企业代码、私有数据或 GPU。至少两篇不同论文实际方法页段可见并形成提取记录。

阶段五：展示每篇论文为什么查、为什么选、哪些页段支持什么思路、如何迁移到最终方案；展示候选原文和复审问题。分别汇总检索来源、下载内容、页段读取论文、采纳论文，保留所有父子 trace、失败委派、未知调用成本，不以父循环成功代替总体成功。关键修改及时同步 GitHub，CI 通过后合主干。

运行入口：`scripts/run_idea_research_live.py`。这是明确绕过 Bridge 的开发 CLI，但调用正式 `IdeaAgent.run_loop`，没有单独拼接候选或自动审批。`--prepare-only` 仅验证输入和保存上下文，不调用模型或工具。子 Agent 从 `configs/agents.yaml` 的独立 `idea_research` 配置出发，按 scenario 显式覆盖模型、工具和预算，并通过 RunRequest.runtime 注入，实际配置一并归档；不修改全局配置缓存。

公开工具预检中 arXiv 元数据接口返回 429，OpenAlex 元数据接口实际可用，因此本轮 scenario 使用自研直连 OpenAlex API 的检索工具，PDF 仍需真实获取受控原文；这不是 MCP 调用。工具预检独立保存，不提供检索结果或论文线索给正式模型。
