# MARS 产品化开发规划与发布验收

制定日期：2026-09-28。

文档用途：供 Codex 连续实施、验证和交付的主执行合同。产品目标、工程实现和验收证据必须一致；本文不代表产品已经开发完成或具备商用就绪状态。文件名与标题不添加容易与产品混淆的文档版本号。

**1. 最终交付目标**

将 MARS 交付为成熟的本地研究应用。其他团队下载、安装后，配置自己的模型 API，选择历史资料、研究代码与数据，按需连接 GPU 服务器，填写研究目标，即可自动完成资料研究、提出方案、设计实验、限定范围修改代码、执行、比较结果和受控迭代。

用户不需要运行开发服务器、编辑多份内部配置、理解 Agent 调度或逐步指挥开发。系统应在启动前集中发现必要缺项；运行中清楚呈现有效进展，支持人工介入、暂停、停止、关闭后恢复；结束后交付可读、可追溯、可复现的完整研究结果。研究未达目标也是可解释的结果状态，不能虚构提升。

本轮必须同时完成：仓库与发行包大清理、成熟前端、通用项目接入、统一 GLM-5.3 调用、稳定且有限的 Agent 循环、CLI、可选 SSH GPU 执行、结果中心、安装升级和真实交付验收。结果呈现属于本轮必做范围；Writing Agent 的论文长文能力不作为首批交付前提。

产品边界为每位用户本地安装、自带 API 和计算资源。首批目标平台：Windows 11 x64、macOS Apple Silicon 客户端，Linux GPU 服务器作为远程执行端。正式支持范围只列实机验证过的系统与架构。账号计费、多租户云平台、插件市场和无限自主研究不进入本轮关键路径。

**2. 用户最终使用流程**

1. 下载并安装应用，直接打开，应用自行管理内部服务。
2. 配置 API endpoint、型号和凭据，完成真实模型及工具调用连接检查。
3. 创建项目，选择历史资料、现有代码、数据和输出位置；允许原地接入外部路径。
4. 选择本地执行，或配置 SSH 主机、端口、用户名、密码/密钥，以及远端代码、数据、Python/Conda 环境、工作目录和 GPU。
5. 系统扫描项目，识别训练与评估入口、指标、基线和修改范围；集中提示无法识别的必要信息。
6. 填写研究目标，查看时间/调用/费用/训练预算，默认采用有上限的自动研究；可以选择逐阶段人工审核。
7. 一键开始，在任务页查看当前阶段、最近有效进展、预算和结果；随时暂停或停止。
8. 结束后直接阅读结论、基线对比、消融、曲线、证据和局限，一键导出报告与复现包。

第二次开展研究应复用已保存项目配置，仅需填写新目标及必要变化。产品提示使用用户语言，Agent 名称、schema、tool call、内部 trace 等放入高级详情。

**4. 技术落地原则**

- 保留已有 Python/FastAPI、前端 React/Next 和可信运行机制，优先收敛与修复。只有有依赖证据及验证收益时才替换模块，避免全仓重写。
- 采用本地桌面应用管理生产构建和后台服务。默认评估路线为 Electron 桌面壳、现有前端生产构建、打包 Python 服务；在工作包 A 完成一次启动/退出/安装验证后固化。若存在可证明的阻塞，Codex 可以选择等价方案并记录决定，不把选型留给用户反复决定。
- 用户安装应用不需要另装 Node、Python、Git 或开发工具。研究代码自身的训练依赖单独检测，优先使用已有项目环境，不能擅自改写系统 Python/Conda。
- UI 与 CLI 必须调用同一研究服务和状态机；禁止继续维护两套领域假设不同的研究循环。
- run/stage/attempt/job 状态、预算、事件、审核与产物引用使用单一持久化权威来源；大文件保存在独立 artifact 目录。可复用现有可靠存储接口，若缺少原子事务则补充事务化存储与迁移，不能靠多份 JSON 猜测真实状态。
- 长训练和远程任务由独立执行器管理，UI 生命周期不直接控制计算进程。LLM 不参与心跳、轮询、进程状态判断或确定性格式检查。
- 应用数据、配置、凭据、缓存和项目文件分离；正式安装目录不得混入用户数据或仓库过程文件。

桌面壳实现须遵守隔离渲染、受限 IPC 和远程内容不获得本机权限的原则；安装包签名和平台验证属于发布工作。参考 [Electron 安全规范](https://www.electronjs.org/docs/latest/tutorial/security)、[打包与签名](https://www.electronjs.org/docs/latest/tutorial/tutorial-packaging)。这些是实现依据，不是已完成的工程事实。

**5. 大清理：代码、目录、文档和发行内容同时收敛**

清理必须贯穿开发，并在最终发布前再做一次干净安装包审计。衡量标准是唯一可信入口、无死路径、无失效引用、无过程垃圾和可恢复迁移，不以删除数量作为成绩。

先保护现场：记录当前分支、提交、改动清单、未跟踪产物及运行进程；在隔离工作区实施。通过可恢复快照保留必要工作，不能覆盖用户未提交修改。没有必要为清理而改写远端 Git 历史或删除用户研究目录。

逐项形成清理清单：路径、所属功能、运行/测试/文档引用、动作、理由、替代入口、恢复依据、验证结果。动作分为保留、迁移、归档、删除：

| 类型 | 处理要求 |
|---|---|
| 当前使用的运行代码、prompts、schema、skills、资源 | 保留并核对运行时加载与打包依赖；不能因代码搜索未命中就删除动态资源 |
| 重复 CLI/UI 入口、分叉流程、失效配置 | 合并到唯一受支持路径，必要时提供迁移提示；完成调用方迁移后删除旧实现 |
| 过时设计、日期化过程报告、截图、临时排错脚本 | 有保留价值的证据移到发行包之外的开发归档；主仓只保留简洁索引和必要回归样本 |
| 无引用且确认无保留价值的死代码、无效占位、废弃脚本 | 小批删除，每批有依赖检查和相关回归 |
| 已入仓构建缓存、生成产物 | 从源码管理移除并完善忽略规则；例如当前 `frontend/tsconfig.tsbuildinfo` 是检查候选 |
| 密钥、个人路径、真实数据、运行历史、用户配置 | 排除发行；凭据不得进入开发归档或交付包；用户资料不随清理删除 |
| 测试与测试夹具 | 保留必要回归；历史证据若被测试消费，提炼为最小脱敏夹具后再归档，不能靠删测试消除失败 |
| 旧徽章、错误版本文案、已失效说明和命令 | 按实际交付改写，移除无法证明的“已验收”“性能提升”宣传；不另造文档版本号 |

发布改为精确白名单：运行代码与必要依赖、必要配置/模板/静态资源、用户说明、许可与第三方声明、空项目模板。禁止直接打包整个工作树、整个 docs/scripts、`.env`、私有数据、研究历史或个人工具配置。

清理验收必须覆盖：动态资源加载、导入/类型检查、相关测试、构建、UI/CLI、真实工具闭环、历史任务读取、暂停恢复、安装包内容和升级。发现未知文件依赖先厘清；不要把“旧文件名”当删除证据。归档放置在明确的开发资料位置，不把 archive 目录原封不动塞进安装包。

**6. 模型、工具库和有限研究流程**

全部生成、Reader、提案、审查、裁判和诊断默认使用 GLM-5.3 系列。实际请求必须记录可核验型号，禁止漏改子角色或静默切回其他模型系列。模型参数与 native tool loop 统一适配，先验证工具调用、结果回传及下一次响应，再扩展能力。

用户已授权本轮开发验证使用其提供的 GLM 测试凭据。密钥内容不写入本文、仓库、截图、日志、打包文件或测试回执；开发时通过本地凭据入口/进程环境注入，不能硬编码。最终产品默认没有开发者共享密钥，每个使用者配置自己的 API。当前规划阶段未使用该密钥发起请求。

能力库必须列出真实生效的 Tool/Skill/MCP、角色权限、schema、依赖、状态和实测回执。正式开放能力须通过真实 GLM → 工具执行 → observation → 后续响应 → 产物核验；缺配置或失败的能力明确隐藏/禁用或阻断需要它的任务。

首批默认 Idea 能力集中在本地资料、arXiv/OpenAlex 检索、来源获取与解析、知识检索、只读基线代码。CVF/NeurIPS 等按领域开启。复用现有工具 ID 和研究委派机制；Skill 是流程规则，MCP 是工具接入方式，不能把本机 Codex 的能力默认当作 MARS 已具有的能力。

固定主流程：

`预检 → 资料缺口检查 → 检索/复用 → 获取与解析 → 隔离阅读 → 候选方案 → 有限评审/评分 → 实验设计 → 限定代码实现 → 实验执行 → 结果评价 → 达标/受控迭代/停止`

- 程序决定阶段顺序、校验、权限、预算和状态；模型处理论文理解、方法设计及基于证据的分析。
- 有足够且版本匹配的资料可复用；新增调研必须对应具体证据缺口。不能无条件重复搜索和阅读。
- 每篇论文独立会话，主上下文接收证据卡和索引；记录实际输入块及页/章节，不把下载或摘要误称为全文阅读。
- 默认形成两个候选、选择一个进入实验；独立方法审查和实验可验证性审查各一轮，一次答复和裁决。只有具体缺口允许有限修订，不采用无限 debate。
- schema、文件存在、参数校验由程序做；论文下载不畅输出待补列表，不持续试同一来源。
- 每次调用必须对应阶段目标及预期产物；无新增证据、相同错误反复出现或工具未产生变化时触发停止/诊断。

**7. 效率预算与性能门槛**

以下是本轮确定的初始产品目标和默认值，不是当前实测结果。开发者可优化实现达到目标；若发现目标不成立，须报告实测与原因，不能静默提高上限后宣布通过。

默认“标准研究”配置：检索候选最多 20 篇、深入阅读最多 5 篇、并发 Reader 最多 2；两个候选选一个实施；一轮辩论；最多两次自动修复/演化。已有充分资料时减少调用，不为了填满额度继续研究。

任务全局默认硬上限：60 次模型请求、120 次工具执行、累计 90 分钟研究活动时间、累计输入 1,000,000 token、累计计费输出 128,000 token（包含供应商计入用量的推理 token，但不保存其内容）、20 元模型调用费用预算。普通单次请求输入上限 48,000 token、输出上限 8,192 token；代码生成可在剩余额度内明确配置到 16,384 输出 token，不能自动无限扩容。训练默认单作业最多 10 分钟、并发作业 1 个、最多使用 1 张 GPU、累计训练进程时长 60 分钟，GPU 路径另限累计 60 GPU 分钟。本地 CPU 路径仍受训练时长限制。

每项预算均可由用户在开始前调整；工作包 A/B 必须将实际值冻结到任务合同，缺失或 null 的必需预算不能启动托管任务。20 元是软件预算设置，不代表服务实际价格或科研任务总成本。GPU 超过标准任务时必须显示预计训练时间和独立上限。

计时分开记录：① 总历时从创建到终态，包含人工等待和跨日暂停；② 研究活动时间是有研究动作、API 请求/重试、外部调用、排队中的已提交训练或正在运行实验的累计墙钟，默认限 90 分钟，并行阶段按时间区间并集计；③ 训练进程/GPU 时间按作业及 GPU 数累计。只有所有实际工作均已暂停或停止时，人工审核/主动暂停时间才不扣研究活动预算。远端仍在训练或排队时继续计时，不能通过关闭应用规避预算；远程 runner 持有独立作业截止时间。恢复继承所有累计用量与剩余额度，不重置；超限任务仅可查看成果，或由用户显式授权增加预算后继续。总历时单独展示，不承诺暂停多日的任务仍在一小时内结束。

所有子 Agent、审查、格式修复、模型自动重试和恢复后的调用都共享账本，不能通过新会话重置。费用依据有来源/日期的价格表和实际 usage 计算；价格不可得时显示未知并依靠有限 token/调用额度控制，不能显示虚假的零费用或宣称精确费用限额已受控。请求前预留最大可能使用额度，超出剩余预算不发起调用。

网络重试采用有上限退避，每操作最多额外重试 2 次；同一错误指纹连续两次没有新证据，终止相同动作并交付当前结果。所有重试计入总时间和预算。监测实验状态、展示进度、压缩确定性日志不得反复请求模型。

| 指标 | 发布门槛 | 测量边界 |
|---|---|---|
| 首次启动 | 生产包打开后 15 秒内可操作 | 标准测试机器，排除首次下载；记录硬件与数据规模 |
| 首轮研究判断 | 20 分钟内给出可审核方案或明确证据不足/阻塞 | 正常 API、至多 5 篇可获取论文；不能用阻塞状态冒充成功样例 |
| 完整轻量研究 | 60 分钟内交付完整结果 | 冻结小任务集，单轮训练/评估预算不超过 10 分钟，最多一次演化；前置依赖就绪 |
| 页面操作响应 | 主要按钮 1 秒内反馈 | 请求尚在执行时也明确显示已受理 |
| 停止受理 | 2 秒内显示，5 秒内禁止新模型/工具/实验启动 | 正在执行的调用可能仍产生服务费用，不能误报为已撤销 |
| 实际停止 | 本地 30 秒内、SSH 可达时远端 60 秒内确认 | 先协作退出，再按已授权策略终止本任务进程组；断连时显示待核对 |
| 状态恢复 | 重开应用后 30 秒内恢复已持久化状态并开始核对活动任务 | 大型远端产物下载不算状态恢复；不重复提交作业 |

GPU 队列、网络故障和正式长训练时长单独记录，不能简单从失败统计中抹去。任意大数据实验都不承诺一小时完成；产品必须在早期给出有效方案、明确训练预算，并在预算到达时结束或暂停，不以持续调用 API 代替进展。

**8. 稳定循环、打断与恢复**

明确区分 queued/running/pausing/paused/cancelling/cancelled/blocked/failed/completed，并将“流程完成”和“研究目标达成”分开表示。每次状态迁移原子落盘，包含阶段、attempt、事件序号、预算、输入版本和产物引用。

- 暂停：停止派发新动作，在安全点保存；正在训练的任务根据适配器能力进入 checkpoint 暂停或明确的继续/停止状态。
- 停止：终止本次研究继续推进，按配置停止所属子进程/远程作业，保存已完成产物及原因。未知远程状态不能标记为已停止。
- 关闭应用：关闭窗口可继续后台研究；完全退出时默认保存并暂停编排，运行中的远程作业按启动时选定策略处理，下次启动先核对。不得关闭窗口就误杀无关用户任务。
- 恢复：校验代码、数据、配置与产物指纹；复用已完成阶段；未完成阶段按明确规则重做。训练精确续训必须有适配器/检查点支持，没有时标记为重启该实验。
- 幂等：同一 job_id 重复提交不重复训练；工具有外部写入副作用时采用幂等键/回执核对。模型调用中断若无法获知结果，标为未知并保守处理费用，不能承诺精确一次计费。
- SSH 断连先标记状态待核对，重连查原 job_id，再决定恢复；禁止直接新开相同实验。远程 runner 有独立训练时限，即使本地退出也不会无限占 GPU。
- 缺依赖、磁盘不足、无效 API、配额不足和数据缺失应明确失败；持久化的结果及已消耗预算不能被清空。

**9. 实验、代码边界和反馈迭代**

Idea 交付人类简述和结构化方案；Experiment 交付基线、候选、必要消融的实验矩阵、逐组 YAML、指标协议、数据划分、种子、入口、预算和成功/否定判据。禁止只交自然语言。

每份实验计划附代码修改合同：允许文件/符号、受保护文件/接口、必须通过的检查和变更目标。Coding 在隔离候选工作区修改，写入工具和最终 diff 双重验证范围，完成语法/编译或导入、单元与数值/shape 检查、基线回归、小数据训练及评估后才能交给正式执行。不得改评分器或删测试来伪造效果。

Execution 冻结代码/配置/数据指纹，按 run/attempt/experiment 存储日志、指标、checkpoint 和 TensorBoard 事件。结果评价先验证实验有效，再按用户指标判定收益。修改训练/评估协议时失效旧比较结果，测试集不得用于无限调参。

执行结束或失败自动触发诊断，路由规则为：环境/调度故障回 Execution；实现问题回 Coding；实验协议/对照问题回 Experiment；实现与协议均检查后假设不成立回 Idea；证据不足先补最小诊断。

每次回退携带证据、原因、允许修改范围、预期影响、需重跑节点和剩余预算。实验计划变化若涉及实现，必须重过 Coding。任务达到目标、预算耗尽、连续无进展或出现不可恢复阻塞时终止并交付真实结果。

人工模式在每两个 Agent 之间可审核、修改和退回；自动模式在预先授权范围内通过同一检查自动前进，自动决策不冒充人工签字。用户随时可切换为人工接管。

**10. 其他团队的项目接入与 SSH GPU**

一个项目配置统一引用知识、代码、数据、输出、基线、命令、指标、允许修改范围、执行环境和预算。用户通过向导完成，不需要搬动既有工程或修改 MARS 核心源码。支持非 Git 代码目录，以文件快照/哈希提供隔离和追溯；Git 项目复用提交与工作区信息。

知识、代码、数据都可为现有目录。自动识别 README、依赖文件、训练脚本和评估配置，生成可审阅的接入摘要。无法确定的指标或入口集中询问一次，必需条件不齐全时禁止烧 API 试错。项目之间不共享未授权的私有知识与产物。

SSH 向导同时支持密码与密钥。凭据只交给连接层；不写入命令行参数、模型上下文、任务 YAML 或日志。连接前核验主机指纹，禁止为了好用关闭 host key 检查。可复用 AsyncSSH 等已有实现，而不是自行实现 SSH 协议；其官方接口提供密码认证与 known_hosts 校验。[AsyncSSH 文档](https://asyncssh.readthedocs.io/en/latest/)

按顺序预检：网络与认证 → 远端路径与权限 → 可用空间 → Python/Conda → GPU/CUDA → 数据存在 → 训练/评估入口 → 小任务运行。每项失败给出可理解原因和修复入口。GPU 服务器未配置时仍可使用本地受支持能力。

明确两种代码模式：使用服务器已有代码/数据；或把本地候选代码受控同步至远端独立工作目录。远端已有代码模式必须完整实施：只读采集授权源码快照与版本/文件哈希供项目理解和 Coding 使用 → 建立隔离候选目录 → 应用/同步限定 patch 并核对哈希 → 部署或核验项目级 runner 与执行协议 → 执行真实小任务。源码按必要范围采集，数据默认留在远端；runner 只在用户已授权的工作目录内安装/升级并保留回滚，不要求管理员权限。

两种模式均不得覆盖原始远端仓库；不默认复制大数据。同步记录清单与哈希，失败支持续传，路径参数安全转义；训练环境选用用户已有环境或隔离项目环境，不默认 root/sudo 安装。

远程作业需具备 submit/status/cancel/fetch/heartbeat，持久化 run/attempt/job 对应关系，断线后训练按既定策略继续且受 runner 时限约束。TensorBoard 通过受控隧道/代理关联本任务，不能暴露无保护的公网端口。只停止本任务进程组，不干扰同服务器其他用户。

**11. 成熟前端的明确验收**

主导航收敛为“项目、研究任务、结果、设置”，只保留一个“新建研究”入口。接入、运行、分析三种工作状态清楚分离；高级配置渐进展开。

视觉建立统一设计规范：排版层级、间距、颜色语义、表单、按钮、表格、状态、图表、空态、错误态和交互反馈。科研工具以信息清楚、操作稳定、密度合理为目标；不用无意义的渐变卡片、炫光、过量动效或占位统计冒充设计。

必须完成以下页面与状态：

| 页面 | 第一屏必须回答的问题 |
|---|---|
| 首次启动/连接设置 | 当前是否能连接模型，缺哪一项配置 |
| 项目接入 | 资料、代码、数据在哪；能改哪里；在哪训练 |
| 新建研究 | 目标是什么；预计做哪些事；预算和运行模式是什么 |
| 运行详情 | 当前做什么；最近有效进展；等待原因；下一步；如何暂停/停止 |
| 方案/实验审核 | 证据是什么；基线/消融如何安排；批准会发生什么 |
| 代码审阅 | 改了哪些文件；是否越界；哪些检查通过或失败 |
| 结果中心 | 是否达标；相比基线有什么变化；证据与局限在哪 |
| 历史与恢复 | 哪些成果已保存；恢复会复用/重做什么 |

不得显示伪造进度百分比、费用或 ETA。不确定时显示阶段、真实用量和未知原因。按钮必须有真实行为；所有加载、空数据、超时、断网、API 错误、SSH 断连、磁盘不足、缺失产物状态都要设计和实测。

在 1280×720、1440×900 及高分屏检查，不出现遮挡、溢出和不可达操作；支持键盘、可见焦点、明确标签及字段级错误。当前执行状态同时用文字表达，不只依赖颜色。

用户测试：至少 5 名未参与开发的目标用户，在资料/凭据/环境就绪后，至少 4 人无需开发者口头指导，在 15 分钟内接入项目并启动首个任务；全部能找到停止、恢复和结果导出。没有这些用户时，可以先完成自动与独立评审，但该项标为待外部验收，不能用开发者自评替代。

**12. 研究结果的规范呈现与导出**

必须由真实运行产物构建统一结果页。首页先给研究问题、结论、目标达成状态、证据强度及局限，再展开技术细节。

标准内容：基线/候选/消融结果表，指标名称/单位/方向，训练与评估条件，样本数、重复次数及实际可计算的波动；真实曲线；修改概要和 diff；论文证据；负结果；失败和迭代历史；费用/用量与耗时；复现信息。缺失结果显示缺失，单次实验不伪造统计显著性。

结论区分事实、假设与解释。优先程序生成可验证的表格和图表；模型只在需要时撰写简短解释，不为了“漂亮报告”重新运行整套 Agent 或大量调用 API。

一键导出两类成果：

- 可阅读报告：本地独立打开的 HTML 与 Markdown，支持 PDF 导出，图表与引用完整。
- 可复现结果包：JSON/CSV 指标、图表、实验配置、环境说明、代码 patch/必要候选文件、数据标识与划分、命令、来源索引、失败记录和清单哈希。默认不打包原始私有数据、完整仓库或凭据。

导出到另一台电脑离线打开时不依赖作者绝对路径、运行中的服务或聊天记录。相对链接正确，包内文件存在，脱敏后的诊断包能帮助定位问题。复现验收还须在独立环境按照包内说明恢复指定基线与候选 patch，接入声明的数据，至少复跑一组实验，并按预先约定的指标容差比对；缺授权源码或数据时列明外部前提，只能标记可审阅，不能标记复现通过。清楚标记“完成且达标”“完成但未达标”“预算停止”“用户取消”“阻塞/失败”。

**13. 本地交付、安全和维护**

- 交付生产安装包与 CLI，包含所需应用运行时；安装、更新、卸载都有明确行为。卸载默认保留用户项目和结果，删除用户数据需显式选择。
- 应用只监听本机必要接口，端口动态分配并处理冲突；本地 API 有会话身份校验，浏览器外站无法发起研究或读取凭据。桌面 IPC 限定操作和路径。
- API 密钥、SSH 密码/密钥口令使用平台凭据存储；不能把解密密钥与密文放一起充当保护。日志、模型上下文、错误消息、截图、导出和安装包均验证脱敏。
- 外部论文和网页是证据，不是执行指令。读取内容不能改变权限、扩大路径范围或获得 SSH 凭据。用户代码执行与 MARS 凭据/其他项目隔离，至少隔离工作目录、环境变量与授权文件边界；按支持平台采用可验证的执行隔离方式。
- 有日志轮转、缓存配额、磁盘预检、任务备份/恢复、升级前快照和失败回滚。保留数据库/产物格式的迁移测试，不得升级后遗失历史研究。
- 正式包有校验值、签名与适用平台的签名验证/公证，提供依赖清单、许可证及第三方声明、已知限制和问题反馈说明。安全扫描的未解决高危问题必须阻止正式发布或给出可复核的不适用依据。
- 默认不上传遥测、研究数据或崩溃包；必要的模型请求和用户选用的外部检索应在设置中明确数据去向。

签名证书、目标系统实机、真实 GPU 服务器或外部用户若不可用，将对应发布项标为阻塞，继续完成其余开发与可执行验证。不能把缺失验证自动豁免，也不能把测试包标为商用就绪。公开发布/购买证书等外部动作按实际授权处理，不把用户要求制定规划解释成已经发布产品。

**14. Codex 工作包、依赖与退出条件**

工作包按依赖推进，每包完成真实验证、更新状态和证据后再进入依赖它的后续包。独立工作并行，明确文件所有权，避免多个 Agent 同时修改 orchestrator、配置合同等公共热点。

| 工作包 | 具体实施内容 | 依赖 | 完成证据 |
|---|---|---|---|
| A 产品基线与清理清单 | 冻结工作树/现有测试；盘点真实入口和动态依赖；制定精确发行白名单；验证桌面壳/后台生命周期；列出删改清单 | 无 | 基线记录、清理清单、架构决定、可打开并正常退出的最小生产壳 |
| B 通用项目与统一运行合同 | 项目路径/命令/指标/保护范围；共享 run/stage/attempt/job/结果合同；迁移现有 UI/CLI；领域参数移入 adapter | A | PIMC 与第二领域配置通过同一预检，UI/CLI 解析同一任务 |
| C GLM 与工具认证 | 统一角色与 provider；修复真实工具循环；生成生效工具库；逐项验证并修复 | B | 所有对外工具/Skill/MCP 的状态、调用和产物回执 |
| D 稳定调度与预算 | 持久状态、取消、恢复、幂等、全局调用/时间/token/费用账本；清除无限分支 | B；真实验证依赖 C | 中断矩阵、预算耗尽、去重、重启恢复和远程未知状态测试 |
| E 高效研究闭环 | 独立 Reader、证据卡、有限辩论、实验 YAML、改动合同、代码检查、受控反馈 | C+D | 真实论文到实验结果完整链路，阶段交接与回退记录 |
| F 项目接入与 SSH | 向导、路径扫描、环境探测、密码/密钥、远端隔离目录、job 重连与产物回收 | B+D | 本地与 Linux GPU 真任务，密码/密钥两种认证、断连恢复 |
| G 产品前端 | 统一信息架构、设计规范、接入/运行/审核/结果页面、全异常状态、键盘与窗口适配 | A+B；功能验收依赖 D/E/F/H | 真实应用逐页截图和操作记录、完整用户旅程、用户测试 |
| H 结果中心与导出 | 通用指标、对比/消融图、证据链、TensorBoard、HTML/MD/PDF、复现包 | B；真实内容依赖 E/F | 另一环境离线打开报告、校验复现包、数据与结论一致 |
| I 大清理收尾与发布工程 | 完成已验证删除/迁移；更新文档；白名单打包；凭据/数据隔离；安装、升级、回滚、签名 | C至H | 干净源码与安装包清单、迁移回归、签名/扫描/许可材料 |
| J 独立发布验收 | 冻结候选包；跨平台/跨领域/效率/可靠性/安全/用户验收；修复后重验受影响范围 | I | 发布判定与完整证据清单；全部必需门槛通过才标为可交付 |

关键路径：A → B → C/D → E → I → J。G 可在 A/B 后并行，F 与 H 随共享合同稳定推进。不得先做外观换肤再把核心运行、接入和恢复留到“以后”。

每个工作包记录：状态、提交、改动范围、实际验证命令/操作、产物、风险、剩余阻塞。状态只允许未开始、进行中、验证失败、阻塞、已验收；“代码写完”不是已验收。

Codex 自主处理常规实现与修复，不要求用户逐包确认。只有缺少无法推断的外部信息、权限或资源时集中报告必要项，并继续不依赖它们的工作。不得因一个平台/凭据受阻就停止所有开发，也不得自称解决未验证条件。

下列是必须执行的发布用例。基于真实模型、真实临时文件、真实 SSH/训练环境；可使用明确标注的合成测试数据进行真实计算，但禁止模型/工具/训练假成功替身。故障测试用可控的真实无效配置、断网、进程中断、资源限制等方式，不伪造服务成功。

| 编号 | 必测场景 | 通过条件 |
|---|---|---|
| R01 | 干净 Windows、macOS 安装与首次启动 | 无开发环境也能打开、配置、启动真实任务 |

先冻结候选构建、至少两个不同领域的小任务、输入/预算和 20 次测试矩阵，再执行真实端到端回归。固定分配：两个领域 × UI/CLI × 本地/SSH 八种组合各 2 次，共 16 次；其余 4 次预先分配给两个领域的 UI/CLI 人工审核路径。矩阵同时覆盖两种客户端系统；SSH 两种代码接入模式及两种认证方式纳入相应组合，不只测最容易的路径。

同一冻结候选构建的 20 次中，至少 19 次正常交付有效结果，且不存在可复现核心缺陷。所有失败完整统计，预期故障用例单独计数；不得删除失败样本或拼接不同构建的成功记录。修复改变候选构建后建立新的 20 次发布批次，旧批次连同失败和修复证据保留；开发期间可以只重验受影响范围，但最终统计必须来自同一候选构建。该样本只作为本轮发布门槛，不冒充长期可靠性证明；“研究未提升”不自动算运行失败。

发布要求：全部必需用例通过；无阻断主流程、数据丢失、重复实验、越权、凭据泄漏、伪成功、无限循环或关键结果错误；性能/可用性符合约定；候选安装包与测试的实际构建完全一致。发现代码或依赖改变时重验受影响范围，不能复用不同构建的通过报告。

**16. 验收证据、最终交付和结果导向执行规则**

Codex 开发期间自行维护任务状态、问题清单、预算和证据，不要求用户管理过程。常规实现不反复征求许可；对外部资源缺失只汇总真实阻塞，不能编造成功。

每个发布用例保存：编号、状态、构建/提交、配置指纹、平台与环境、起止时间、run/attempt/job、实际模型、调用数/token/费用、输入与产物哈希、日志/截图/报告位置、失败原因及重验记录。秘密脱敏，私有研究材料不公开发布。报告生成程序核对证据存在且互相匹配，不能只依赖 Agent 自评。

最终必须交付：

1. 干净且可维护的产品源码、依赖锁、唯一受支持运行入口及必要回归测试。
2. 实机验收过的安装包和 CLI、校验值、签名状态与支持平台清单。
3. 新用户快速开始、项目接入、SSH 使用、暂停恢复、结果导出、故障处理和升级说明。
4. PIMC 与第二领域的真实示例结果及可复现配置，不包含用户私有数据或开发密钥。
5. 工具认证报告、清理清单、包内容清单、性能/稳定性/跨平台/UI/安全验收报告及证据索引。
6. 仍存在的限制与阻塞，以及明确的发布结论：可正式交付、仅可测试分发、或未达到发布要求。

不能将“页面能打开”“单元测试通过”“模型有响应”“生成了方案”或“打出了安装包”分别冒充商用产品完成。所有必需门槛达到后才报告本轮目标完成；没有达到时交付真实状态与可用成果。
