# 对话内任务恢复验证

2026-09-29。失败任务在研究对话中显示恢复操作，不需要总控先读取失败产物。

- `run.recovery_status` 与页面使用同一准入逻辑；`run.recover` 与页面共用恢复服务。
- 检查点可用时支持继续原 invocation；否则仅对已失败阶段提供显式重试，沿用原 run 和上游产物。
- 绑定项目、节点和状态摘要；拒绝过期操作。已有执行所有者时不再启动第二个任务。
- 未确认的模型调用、工具操作、历史执行状态，以及损坏的账本或耗尽的累计预算会阻塞恢复。
- 重试沿用既有 revision 机制：保留历史调用、token 和费用，只为显式的新阶段尝试建立执行时间窗口。恢复状态查询不修改账本。
- 总控提示词要求用户说“继续、恢复、重试、重新编码”时优先检查并恢复关联任务。该提示词不是模型行为的绝对保证；页面按钮直接调用服务。

验证：

- 恢复准入、执行所有权、预算、总控及生成恢复相关单元测试；使用真实临时状态文件、真实异步锁和预算账本，无模型成功替身。
- 全后端及发布脚本 strict mypy；前端生产构建与类型检查。已有无关 lint 提示仍存在。
- 本地实际失败 Coding 任务返回“重试当前阶段”，浏览器确认按钮出现在对话内。
- 对实际任务提交故意过期的恢复令牌，返回 HTTP 409；前后 run_state 与预算文件哈希一致。
- 未点击用户任务的执行按钮，未重跑 PIMC 实验；本次验证不代表完整研究恢复后已成功完成。

限制：执行结果未知时仍需人工核对回执；服务或 API 配置故障需修复后再操作。用户主动停止的任务与历史只读任务不自动解除停止状态。
