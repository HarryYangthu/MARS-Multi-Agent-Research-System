# Repository-backed baseline handoff

## Failure and change

A real project repository could be read during research, yet Coding failed before
its model invocation because admission only recognized pasted `baseline_code`.
The bridge now resolves concrete code evidence references from the approved Idea
in the current bound repository. It checks actual files, configured path permissions,
project identity, and content hashes before supplying a typed availability receipt.
It does not claim the model consumed those files; contents remain tool-mediated.
Caller-supplied text is preserved. Missing files, escaping paths, credential files,
and foreign-project references cannot satisfy the prerequisite.

Selected run dataset metadata also retains its typed data-description identity at
handoff instead of being available only under an unrecognized label.

## Verification

45 targeted real-file and pure contract checks passed across repository handoff,
task contracts, Commander feedback, and research handoff tests. No model, tool, or
external service success was substituted.

In the fresh product journey, three approved baseline references resolved to the
actual attached repository. The same task's Coding retry entered its real ZCode
invocation without resetting the cumulative model budget. Simulation and reporting
remain separate verification steps; this receipt alone is not full-flow acceptance.
