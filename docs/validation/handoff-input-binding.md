## 修复

- `kind` 保留资料分类职责；新增 `context_ref` 明确引用命名输入。历史已知类别仍能兼容原来的同名字段；通用 `other` 不代表任意输入，也不会从描述文字猜测绑定。
- 两种研究 Agent 的新提交 schema、提示和交付检查均要求阻断性特殊资料填写非空 `context_ref`。缺失在方案生成阶段反馈，避免等到执行才发现协议不完整。历史批准文档保持可读，未降低实验、科学审查或代码交接标准。
- 统一只读 `inspect_handoffs` 给实际调度、恢复预检、仿真配置预览使用。尚未解决的输入不会提供无效重试；错误包含实际输入名称或待绑定条件。检查本身不写交接结果。
- 已批准历史文档仅允许显式绑定修复，记录 `input/handoff_context_bindings.json`。绑定包含任务、项目、批准文档 SHA、原条件 SHA、明确输入名称、输入 SHA、可选文件内容 SHA，以及授权来源和原因。不能覆盖原有明确引用、修改研究条件或静默替换冲突记录。任何来源或内容变化都会阻断旧绑定；绑定身份也进入配置核对 token。
