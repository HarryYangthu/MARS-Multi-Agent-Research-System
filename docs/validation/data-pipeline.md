# 项目数据管线

入口：项目配置 → 代码与背景 → 数据管线。无需先启动研究任务。

## 数据与处理

支持 MAT（非 v7.3）、NPZ、NPY、PTH/PT。PTH 使用 weights_only 加上明确列举的 NumPy 数值构造类型，不回退到任意 pickle 执行。字段、采样轴、采样率由用户确认；不会从文件名猜测 RF 频段。上传原始数据保持不变，每次处理生成独立记录和 NPZ。

- 移频：从项目关联仓读取 `libs/data.py:data_sft`，记录文件哈希。
- 频谱：优先从关联仓读取 `tools/tf_intake.py:spectrum`；较旧 PIMC 仓使用 `libs/dsp.py:_psd_db` 中明确指定的 SciPy fallback，非 std_lib 校准结果。二者均为 Kaiser(1024,10)、FFT 2048、双边 Welch。图显示选定通道处理前后 PSD；数值分析覆盖所有通道。
- 时延：SciPy 互相关，直接参考或单带三阶参考 `x*abs(x)^2`。指定一个数字通道估计公共时延，也可手填整数时延。信号和参考同步裁边，不循环填充。参考方式沿用仓内 `correlate_analysis` 的单带思路，不能当成多频段 IMD3 映射。
- 滤波：独立的 SciPy Hamming FIR 低通，不冒充缺失的历史 `std_lib`；有效卷积裁除边缘，参数记录在处理记录中。
- 处理顺序：移频 → 时延裁边 → 低通。全部通道一起处理，图/估计通道从 0 起；原始频率域及时间基准需由用户确认。频谱是数字幅度 dB/MHz，非 dBm。频谱使用明确标识的前缀样本，RMS 为整个选定数组。

具体数值函数保留在外部研究仓，仅加载被点名的函数定义；不会导入该仓的训练入口或把研究源码复制入 MARS。这里只支持已核对的 PIMC 函数接口，不自动执行任意仓中的整套流水线。

## 简报与交接

处理完成后点击“LLM 分析”。`configs/data_pipeline.yaml` 配置分析角色（默认使用 writing 的现有模型连接）、数值资源上限和简报提示。模型收到统计量、处理参数和源码来源，不发送原始数组。目标150–250字、最多3条，上限350字；超长时自动再请求一次精简，原稿和两次用量保留；仍超长或空响应明确失败，可以重试，已处理数据保留。

输出使用 `report.v1` frontmatter 校验；模型用量写入该处理记录，只统计。用户点击“用于后续 Agent”后发布为 `context/MARS_DATA_ANALYSIS.md`，下次研究创建时作为 reference 快照加载。已运行任务不被悄悄改写。每版简报和完整参数保存在项目元数据 `data_pipeline/<id>/` 中。

## 验收

32 项数据管线、数据源和项目背景相关测试通过；672 个文件的严格 mypy 及四条架构依赖检查通过；前端生产构建通过（已有页面保留原有 lint 提示）。纯数值测试使用明确的合成信号验证移频峰值、滤波、配对裁边，实际调用外部 PIMC 两种频谱实现，不伪造工具或模型。

独立临时验收项目读取真实333MB PTH（16×196608、Tensor+NumPy混合字典），生成频谱和独立NPZ；真实GLM-5.3调用返回简报，report.v1校验通过，发布后自动上下文API把它识别为reference。该诊断不代表模型训练或抵消性能提升。

限制：MAT v7.3需先转普通MAT/NPZ；时延为单通道估计的公共整数时延；未实现逐通道/分数时延、重采样或自动射频频段推断。后台任务在进程重启后标为中断，可重跑；尚不支持从数值运算中间续算。数据管线不是训练流水线。

最终真实模型简报为101字，自动精简调用共两次；已完成共享与项目上下文读取验证。
