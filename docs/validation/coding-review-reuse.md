# 编码审核中的复用与补丁验证

## 已修复的问题

相同内容的成功重写会生成真实工具记录，但不会产生代码净差异。此前审核把空差异误判为没有写入记录，随后尝试应用正文中的示意 diff；缺少文件头和行号的片段因此导致补丁语法错误。

- 核验结果保留成功写入记录数和已核验的无差异文件。只有完全没有写入记录时才允许旧的补丁交付路径；有记录的清单不一致必须修正，不能回退到旧补丁。
- Bridge 给 Agent 注入通用的候选验收回调。编码清单与实际写入链不一致时，将真实净差异和复用文件反馈到现有模型修正循环，在人工审核前阻断错误交付。保存产物前再次检查；权限、保护范围和源码指纹核验继续生效。
- 复用文件不会算作新增；同一任务此前确实新增的文件在重试时仍属于净新增。外部改动、部分实现、损坏快照、文件类型不一致继续拒绝。
- Markdown 的示意 diff 保留作为说明；只有通过完整统一补丁解析的内容才导出为可执行补丁。旧的无效片段在派发工具之前返回明确提示。
- 审核使用当前选中的 Markdown 版本，补丁版本不能替换被核验的方案版本。
- Git 任务中的真实代码检查子进程继承同一个已验证的 Git 环境，避免检查内部的 Git 调用重新落到不可用的系统程序。

## 验证

56 项相关回归检查通过，使用真实临时文件、真实 Git 分支、受治理写入和实际检查子进程，不使用工具或模型替身。覆盖原任务恢复、版本一致性、复用、撤销改动、旧补丁、完整补丁、快照损坏及真实子进程的 Git 选择。10 个源码和测试文件通过严格类型检查。

实际研究任务的两个复用文件与写入前后指纹一致，最新人工可审核方案声明空净改动；核验没有重复应用补丁，也没有批准或启动仿真。真实项目完整检查重新执行：119 passed、6 warnings、退出码 0。警告保留，测试通过不代表研究性能达标。
