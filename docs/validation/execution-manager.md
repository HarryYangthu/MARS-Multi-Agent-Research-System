## 已实现

- Coding 交付 schema 中的 `execution_jobs`，逐项绑定批准矩阵的名称与实际入口/配置文件或MARS `command_id`。执行侧拒绝覆盖批准参数或增减实验。
- 配置确认保留在主聊天中；交接清单自动校验，不再额外审核模型生成的执行方案。明确托管模式由策略确认。
- 预览和启动共用准备逻辑，不再按关键词或全局默认数量截断矩阵。每个排队作业启动前再次检查配置确认。
- Paper-static 读取每组绑定文件；明确入口、整数种子、轮数预算和输入身份。该真实入口的 `--max-iters` 限制完整训练轮数，不是优化器步数；步骤预算冲突必须回到实验设计，不能猜测换算。
- 每组状态和真实执行收据落盘。复用完成作业前验证测量证据哈希。重复领取、运行状态不明、证据被改动均阻断重放。
- 并发取消等待全部子进程清理完成。用户显式恢复中断阶段会保留旧记录，生成新的配置确认，禁止沿用旧批准清单开跑。
- 真实指标包含实验名称、状态、测量来源哈希和耗时；主聊天中完成结果可展开/收起。TensorBoard、实测曲线、日志仍由MARS收集。
- 模型预算记录原样保留；确定的执行清单不需要模型请求预留。未知模型调用、协议冲突和真实作业预算仍需要按各自规则核对。

## 已有模型直接运行的配置

快捷运行使用项目执行配置中登记的入口与配置路径。显式提供的配置未登记时，MARS 会读取该文件并返回登记缺口；不会据此认定模型不存在，也不会扩大执行范围。创建、启动状态以实际工具回执为准。

未固定种子的项目可以在对应执行 profile 中设置 `seed_policy: generate_if_unset`，并用 `seed_defaults` 明确列出入口实际加载的默认配置文件（没有默认文件时填 `[]`）。MARS 按登记顺序读取默认配置，再读取所选配置；用户指定的种子或源码已经固定的种子优先。没有固定种子时，仅在创建新任务时生成一个 32 位种子，标记来源为 `generated_for_run`，写入任务和执行交接资料，后续阶段复用这个值。该种子是本次运行的记录，不是历史基线的原始种子。

训练预算保持原单位：`一个 epoch` 表示完整遍历一次训练集，不换算为一次参数更新。失败后明确要求继续或重试，且尚未创建任务时，MARS 保留原请求的预算；已经创建的任务使用原记录恢复，避免重复创建。
