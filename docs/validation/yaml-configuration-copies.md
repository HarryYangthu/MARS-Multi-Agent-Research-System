# 批量复制 YAML 配置并改参

已有模型只调整学习率、批大小、抽头数等配置字段时，Coding 使用 `code.copy_yaml`，从已读取的真实配置派生变体。模型只提交源路径、目标路径与参数差异，不逐份输出完整文件。

```json
{
  "source": "configs/static.yaml",
  "common_updates": {"seed": 2026, "Epoch": 2},
  "allow_new_keys": true,
  "variants": [
    {"path": "configs/comparison/baseline.yaml", "updates": {}},
    {"path": "configs/comparison/candidate.yaml", "updates": {"lr_init": 0.0002}}
  ]
}
```

`common_updates` 应用于全部变体，单项 `updates` 覆盖同字段。字段使用嵌套 mapping，默认只能修改已存在的标量字段；新增已明确的字段须显式设置 `allow_new_keys`。不猜测训练预算、配置继承和模型结构。目标路径仍须匹配项目实际登记的运行命令。

工具保留未改变的原文、注释、顺序和换行。先验证全部目标及解析结果，再落地；源文件不覆盖，目标不能重复。每次调用最多 128 组配置，保留写前和写后快照，支持回滚和代码审核。只读目录、保护路径和任务隔离继续生效。受限配置变体不按通用源码重构的文件数量触发额外审批。

移动配置目录前先核对真实加载器。例如加载器使用同目录 `base.yaml` 时，先用该工具单独复制真实 base，再生成变体。别名、合并键、序列改写等复杂编辑可使用既有写入工具，不能猜测或丢弃原配置内容。不为整理目录删除本任务已留下的配置。

纯配置改动核对实际差异，并由登记的训练入口逐组执行不训练预检。不额外生成仅复述参数的新测试，也不修改模型或可视化实现。源码、加载器或入口确有变化时，按影响范围执行真实测试。

重试编码前，MARS 提前向首稿上下文提供本任务已核实的全部净改动清单，包含之前保留的写入和复用项。清单只来自真实写入记录与当前文件校验，警告和超限如实保留，不补造、截断或自动批准。这样可以避免首稿漏列上一轮文件后再增加一次模型修正。

`code.test_runner` / `code.lint` 可在同一任务、同一 MARS 进程中复用成功的真实检查收据。复用返回 `reused=true`、`check_started=false` 和原收据引用。指纹涵盖 Git 可见文件（含未跟踪和已删除文件）、命令、清洗后的环境、Python 环境安装记录、工具策略和冻结的数据。输入变化或证据不完整时仍实际运行；失败不缓存。忽略的生成文件和安装库内部源码不属于该指纹，不能把收据复用当作新执行、训练结果或人工批准。

验证覆盖真实批量写入、未指定字段保持、注释和换行、拒绝越界与保护路径、回滚、写入归档、改动审核、真实子进程收据复用及输入变化后的失效。
