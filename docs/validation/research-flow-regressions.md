# 研究流程故障回归

## 修复完成的标准

用户按真实操作流程试用时，每个问题都需要保留以下记录：触发操作、原任务和阶段、真实日志、根因、修复、同类边界条件、可重复验证及仍未验证的部分。按钮恢复或状态变绿不单独代表通过。

每次修复需要同时检查正常路径、明确拒绝、请求结果未知、重复点击、刷新和后端重启。失败必须保留已批准文档、实际代码及累计用量；结果未知不得自动重放修改、模型调用或实验。修复对应的自动检查纳入持续集成。后续改动破坏这些约束时，检查必须失败。

| 重试或重启掩盖用量、未知操作 | 持久账本与原任务检查点保留；拒绝重放未确认请求，重试不退款 | `test_model_accounting.py`、`test_model_attempt_budget.py`、`test_loop_generation_resume.py` |

总预算预留、恢复提示共用 `model_request_capacity`，计入最坏情况下的 SDK 尝试次数；实际尝试明确结束后，只计入已发生次数。未知或取消结果仍保守保留。`statistics_only` 下 Token 仍累计统计，不参与总量阻断；上下文容量和单次输出限制继续有效。已有合同执行的独立约束保持有效。

模型循环的预算停止现在保留明确原因与 `request_sent=false` 的证据，传回调用层，避免丢失成泛化的“loop failed”。没有预算时不发送请求，也不产生实验成功记录。
