# 交接与主控审核输入修复（2026-10-12）

当前任务 `2026-10-11T1824_pimc_ca_sparsity_g1c17` 在编码模型调用前报
`handoff_context_missing`。方案已在 `method_spec.code_check.files[].path`
列出实际代码，但宿主只识别 `evidence_refs[kind=code].ref` 和实验的
`base_config`。这些字段未填时，已接入的仓库被误判为缺少基线资料。

交接现在也接受上述明确路径，并用原有项目、路径、忽略规则和文件存在性检查
重新读取文件哈希。自然语言描述不解析为路径，生成的新配置不冒充既有基线，
模型自报的哈希、已读结论也不作为宿主证据。可读取不等于已理解或实验通过。
Idea 提示补充结构化代码引用约定，减少后续交接歧义。

同一任务的主控审核记录显示，实验方案因超过独立的 60,000 字符门槛而转为
`needs_user`，后续批准者为用户。该旧门槛现由统一输入预算替代：取审核配置、
Commander 角色输入设置、运行时上下文预算和模型剩余空间的最小值。输出额度
不扩大输入预算；当前输入仍为 128,000。旧 YAML 的 `max_input_characters`
兼容读取，但不再作为独立限制；可用 `input_token_budget` 显式收窄审核预算。

审核保留完整文档，不静默截断；估算使用 UTF-8 请求字节上界而非真实计费 token。
超出预算时记录 `review_context_budget`、估算值、配置值和完整输入哈希，明确暂停，
不推断批准、不重放结果未知的审核。真正的证据缺失、权限、科学歧义与系统 Gate
仍保留；产物和仿真配置均继续由主控真实审核，助手不代批。
