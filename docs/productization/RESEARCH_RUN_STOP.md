# D/G 增量：合同研究的持久停止

产品 `POST /api/runs/{run_id}/stop` 现在可控制合同任务持久登记的本地作业，包括当前服务没有原执行协程的重启场景。它不启动研究、不重新提交作业，也不建立第二套 RunGraph。完整研究 start 仍保持阻断。

停止首先在原 StateJournal SQLite 事务中写入 `cancelling`，禁止新的模型、工具、阶段和作业准入；HTTP 202 只表示停止请求已持久保存。后台核对原 SQL 作业目录、实际 runner 回执、阶段独占锁、当前进程协程及预算活动记录，全部确认后才在同一状态图写入 `cancelled`。尚在 running 的节点记录取消原因并转为 failed；既有产物、审核记录、已完成节点和累计预算保留。

已有调用或未知活动仍可能产生费用。未核对的活动不退款、不清零，也不显示“已停止”。停止页区分请求已保存、正在核对、核对未完成、状态保存失败和确认已停止。后台单轮失败不会重新提交研究。

SQL 首次写入等待上限为 1 秒；后台轮询周期 0.1 秒、协调窗口 30 秒，由 `configs/research_jobs.yaml` 配置。每个作业控制还有独立锁/适配器时限，因此该窗口不是任意作业数量、损坏存储或远端环境的统一停止 SLA。

## 失败边界

- HTTP 等待方被取消后，独立停止请求继续完成事务和实际作业控制。
- SQL 状态拒绝写入时仍取消已归属协程，并尽力控制身份可核验的 SQL 作业；不宣称派发屏障已建立或整次研究停止。
- 外部冻结合同丢失时，仍尝试停止原 SQL 登记的作业；预算无法验证时保留 cancelling。
- UI 缓存通知失败不阻止实际停止，也不改写 SQL 事实。
- 缺失/占用的阶段锁、未结束预算活动、未知作业及目录漂移均保留未确认状态。重复停止不重建合同、预算或提交身份。

## 实际验证

14 项新增测试使用真实 SQLite、文件锁、FastAPI 与本地 CPU 子进程；没有模型、工具或服务成功替身。相关取消和逐项作业控制回归共 **55 passed、1 skipped**。跳过项缺少历史真实研究 checkpoint。

生产浏览器实际点击停止 run `2026-09-28T0252_task` 的 `actual-stop-ui-job`：HTTP 202 资源计时 **6 ms**，持久请求到最终确认 **0.117266 s**；真实命令在计算指标前被取消，未生成或宣称实验指标。唯一原提交保留，模型请求为 0，实际进程时间已结算。生产构建 `WiHH-cqKbXDm79sH-aVns`。[可核验回执](evidence/research-stop-browser.json)。第一次界面检查和修正前截图仍保留，不冒充同一构建的发布验收。

这些证据只覆盖可信本地 CPU 进程和本次停止链路；不覆盖 SSH/GPU、OS sandbox、完整研究、暂停/checkpoint 恢复或最终发布矩阵。浏览器跨服务停启的旧会话记录了未捕获轮询 fetch 错误，单独保留并继续修复，不能宣称所有断线界面已验收。

完整回归 **3475 passed、181 skipped（214.83 秒）**；strict mypy **643 文件**、4 条导入合同、前端生产构建/类型/相关 ESLint 均通过。[检查回执](evidence/research-stop-checks.json)。
