# 项目创建中的配置步骤

点击项目页「新建项目」，先创建文件夹，再在同一个弹窗中逐步配置。项目页和设置页不再提供独立的新手引导模块；旧 `/onboarding` 地址重定向至 `/projects`。

1. 选择保存位置和项目名称，创建项目文件夹并注册。该文件夹保存项目身份与背景资料；代码工程可在后续步骤单独导入，无需复制进 MARS 仓库。
2. 自动进入 API 配置，带入已保存的连接，支持保存、真实连接测试或稍后配置。这里沿用全局模型连接配置，保存前明确说明会应用到启用角色；不暗示各项目拥有独立密钥。
3. 在「代码与背景」中导入用于研究仿真的基线代码仓，并上传一份 Markdown/TXT 背景。代码通过 `.mars/repo_link.yaml` 关联，源码不复制、不移动；上传内容保存为当前项目根目录的 `README.md`，文本不改写。再次上传更新 README，旧版保存在 `.mars/background-history/`，不作为当前背景加载。背景用于已有工作、术语、数据说明等，不要求填写本次研究目标。
4. 完成配置后关闭弹窗。本次研究目标留到后续研究对话中描述；配置页不再提供目标填写入口。完整研究启动仍保持阻断。

已保存的内容持久保留。项目卡片直接提供「项目配置」按钮，点击即可再次进入这些步骤，自动读取已保存的 API 配置和该项目的背景资料；无需重新创建文件夹。「项目资料」内也保留继续配置入口。API 保存、连接测试或上传进行时禁用步骤跳转及关闭/Escape，避免中断时误以为操作取消。API 表单在前后步骤切换时保留输入。

上传通过 `api → bridge/project_onboarding → harness`，沿用项目文档数量/字符预算与项目上下文快照。README 原子替换前保存旧版字节；上传失败回滚，不改写 AGENTS 或单独关联的基线代码。旧项目 `context/` 下的额外资料继续兼容，不自动删除用户文件。

## 模型连接测试（2026-09-28）

“保存 API 配置”旁新增“测试连接”。通过 `api → bridge/model_connection_test → harness/llm` 发送一条真实简短模型请求；不保存表单配置，不启动研究，不发送项目背景。只有收到非空真实响应才显示成功，并显示请求模型和耗时。修改表单后清除旧测试结果。

测试沿用原生 provider 和模型 reasoning 兼容参数。服务端默认 30 秒超时、零自动重试、单进程最多一个测试；前端 40 秒停止等待。具体策略在 `configs/models.yaml` 与 `configs/frontend.yaml`。密钥缺失、鉴权失败、额度/限流、请求拒绝、服务故障与超时有独立提示，异常正文与密钥不返回浏览器。请求体有大小限制，验证错误也不回显输入。

验证：36 项连接/配置/项目引导/模型注册测试通过，包括真实拒绝连接、真实不响应 TCP 连接、并发拒绝、零重试与敏感字段不回显。strict mypy 646 文件、4 条依赖合同、相关 ESLint 和生产构建通过（现有其他页面仍有 lint warnings）。在生产浏览器点击按钮，用已保存的智谱 glm-5.3 配置得到真实成功响应，界面耗时 1.16 秒。测试前后模型配置、角色配置、密钥文件逐字节摘要一致；该测试不代表各研究角色、工具或完整研究执行通过。

## 代码工程与补充背景（2026-09-28）

「项目上下文」更名为「系统将读取的资料」：AGENTS.md 是项目约定，README.md 和上传文档是参考背景，代码由工具按需读取。此列表不表示资料充分，也不要求用户补齐额外表单。新建项目的模板不再提示在文档中填写本次目标；已有用户文件不被改写。

代码导入经过 API → bridge，验证真实本地目录并原子更新当前项目的 repo_link，保存基线代码路径与用途，启用 read_only，保留项目身份、保护和忽略规则。背景资料留在项目资料目录，关闭并重新打开项目不会把代码关联改回默认。上下文提示不再错误地把资料目录称作代码仓。

验证：30 项实际文件/API/代码读取测试通过，涵盖 TXT 保持文本、同名拒绝、导入后真实代码读取、重开保留关联、非法目录/符号链接拒绝及源码不修改。strict mypy 646 文件、4 条依赖合同、TypeScript、相关 ESLint、生产构建通过。浏览器在独立验收项目真实导入目录、上传 TXT 并重开确认，上传内容字节相同，源工程只有原文件，未捕获 JavaScript error。未发起模型调用或研究。

## 仿真基线用途与写入保护

导入对象明确为研究仿真基线仓（源码、依赖、仿真配置及运行脚本），不是普通附件或可直接改写的工作目录。确认导入会写入 `repo_role: simulation_baseline` 和 `read_only: true`，并在 UI 显示真实配置的代码写入保护状态。该保护约束 MARS 代码写入工具，不是操作系统权限变更。已存在的旧关联不会仅因显示页面就宣称受保护，需确认导入以启用；用户已有源码和项目规则不被改写。

正式任务的实验修改沿用运行绑定的独立 candidate workspace 与授权路径，不用原始基线作为可写副本。78 项项目接入/运行范围测试通过，包括实际读取基线成功、直接代码写入被拒绝且原文件未变；相关 strict mypy、TypeScript、ESLint、生产构建通过。生产 UI 在独立验收项目确认导入并显示写入保护开启，未执行仿真或宣称基线科学指标已验收。

## 背景统一为 README 与可选 Agent 规则

新建项目不再生成占位 README；用户上传一份 Markdown/TXT 后，系统将其保存为 README。即使上传文件名是 AGENTS.md，也只保存为 README 参考资料，不提升为操作规则。已有 README 的替换按剩余文档容量计算，保留原字节备份；符号链接、硬链接、未纳入读取范围与容量超限均拒绝或回滚。上传成功可展开查看备份位置。

AGENTS.md 保留为可选长期规则文件。填写指导保留在模板中，可通过文件行的“查看模板”按需阅读：

- **写什么：** 基线保护、可写目录、必须保留的接口、仿真运行要求等真实适用的规则。
- **谁写：** 用户或项目维护者确定，AI 可起草，由用户审核后保存。
- **何时写：** 有明确约束时，在 Agent 修改代码或运行仿真前补充；可跳过并以后更新。目标在对话中提出。
- **如何更新：** 编辑项目文件夹中的 AGENTS.md，保存后重新扫描。新任务读取更新，已有任务文件快照保持不变。

系统精确识别未修改的新旧模板，以 `is_template` 标记。UI 不将占位 README 列为背景，AGENTS 空模板显示“可选 · 待填写”；模板也从 Agent、Commander、项目层、文档搜索及 CLI 自动上下文中排除。手写或修改过的文件不按模板处理；旧快照通过内容识别兼容，不重写历史文件。

验证：41 项项目上传/目录测试通过；相邻上下文、CLI、Gate 回归 67 项通过，7 项依赖未配置的外部静态研究仓而跳过。修改文件 strict mypy、4 条依赖合同、前端类型检查及生产构建通过；其他页面既有 lint warnings 保留。真实生产浏览器完成上传、README 预览、旧版备份与重扫描；背景内容与上传文件一致，当前有效背景仅一份，AGENTS 空模板未当作规则加载，未捕获 JavaScript error。未发起模型请求或仿真。
