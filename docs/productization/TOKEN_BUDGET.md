# 分项模型预算增量

2026-09-28。工作包 D 的局部修复，不代表共享事务、活动时间或整套研究预算已验收。

默认资源策略分别限制输入 1,000,000 token、计费输出 128,000 token，并保留两者合计上限。请求前按已有保守输入字节上界和 max_tokens 为所有可能 SDK 尝试同时预留；任一分项不够就不发起请求。输入上界可能高于实际 tokenizer 计数，因此准入可能早于实际额度耗尽；这不是精确费用估算。

只有完整有效 usage 才结算。prompt_tokens 归入输入，total_tokens 减 prompt_tokens 归入输出；供应商计入 completion 的推理 token 不丢失，额外未解释差额也保守记在输出，且不保存推理内容。失败、重试响应不完整、取消或 owner 丢失保留两项原始预留。旧账本若没有分项，执行时保守将原总量记入每个未知分项；报告显示分项未知，不编造零用量。已知账本的分项和必须等于总量，损坏时拒绝后续调用。

验证：原模型账本、SDK 尝试和报告回归加新分项测试共 64 项通过；随后新增报告字段与未知用量测试，相关 29 项通过；3 个改动 Python 文件严格 mypy 通过。测试仅对实际临时账本进行预算运算、真实拒绝连接及进程失联检查，没有模型/工具成功替身。

此阶段仍使用既有模型账本文件锁；没有宣称与 Run 状态一起提交。现有 elapsed 上限仍不同于计划要求的活动区间并集。工具/训练/GPU 等预算、任务合同到运行策略的统一准入、费用表来源核验均需后续工作。费用未知时仍明确显示未知。

独立审查又发现报告只校验分项非负、未检查两项和等于总量。已复用运行时一致性校验，损坏账本的报告总量与分项全部标未知并附警告，增加真实临时账本的损坏输入回归。
