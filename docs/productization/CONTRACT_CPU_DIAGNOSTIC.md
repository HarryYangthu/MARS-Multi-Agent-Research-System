# 真实 GLM、文件工具、CPU 作业与结果账本组合诊断

2026-09-28，在本机 macOS / Python 3.13.9 上执行 `scripts/verify_contract_cpu_loop.py`。本次实际运行是开发诊断：合同任务仍为 `created`，直接调用受冻结合同约束的主机接口，没有解除产品研究启动门禁。

## 实际执行

1. 原生 GLM-5.3 循环读取说明及候选文件，通过已注册的文件工具把隔离候选从线性特征改为二次特征。原始四个源码文件不变。
2. 同一冻结合同、同一 SQLite 账本提交基线和候选各三个真实 CPU 作业；每个种子的两组使用相同训练/评估数据。六个独立作业均产生实际完成回执和逐行预测 CSV。
3. 第四次真实 GLM 请求解释实际指标；结果服务核验回执，再导出 HTML、Markdown、JSON、CSV 与清单 ZIP。

数据由明确编写的生成器产生：`y = 0.4 + 0.6x + 1.3x² + ε`，`ε` 的标准差为 `0.04`，每个种子使用 64 个训练样本和 64 个留出评估样本。这里的已知二次关系用于执行接口与数值一致性诊断，不是新颖科研发现、独立科学审查或 PIMC 实验。

| 种子 | 基线 MSE | 候选 MSE |
|---|---:|---:|
| 41 | 0.1327328222 | 0.0019598813 |
| 42 | 0.1427797688 | 0.0023337288 |

共享账本记录 **4 次实际 SDK 尝试、5395 输入 token、1117 计费输出 token、3 次文件工具执行、1 个进入实现的候选**。六个 CPU 作业的进程时长累计约 0.141 秒；所有相关预留已结算，没有活动作业或未知预留。费用没有核验价目，保持未知。原生编码循环本身为三次请求，第四次解释请求另行计入同一账本。

## 独立复核及模型错误

独立只读复核逐行重算六份 CSV 的预测值、平方误差及 MSE，核对同种子两组的输入/目标一致，SQL 的操作身份、冻结命令、执行快照、模型回执与作业回执一致。ZIP 中八个 payload 的字节数与 SHA-256 均与清单吻合。复核前后 152 个证据文件的字节与修改时间不变，没有额外调用模型或训练。623 条一致性/算术断言不是 623 项产品测试，也不代表另一环境复跑。

**原始模型总结存在一项解释错误：它把 `0.04` 称为噪声方差。实际生成器的 `random.gauss(0, 0.04)` 使用标准差，方差为 `0.0016`。** 原始模型输出保持不变，此处单列更正；该总结不能作为已通过科学审查的结论。
