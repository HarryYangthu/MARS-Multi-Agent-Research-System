# 公司内网慢模型

主控决策与完成检查遵循所选模型的 request_timeout_seconds，额外保留取消请求的宽限时间。此前的 60 秒、30 秒上限已移除。已完成的工具结果和已有任务不会因为后续模型超时而删除。

## 启用慢模型配置

1. 将新版核心代码 ZIP 拖到现有安装目录的 Update-MARS.cmd 上，等待更新结束，依赖和项目无需重新复制。
2. 运行 stop-mars-windows-native.cmd，停止更新检查后启动的 MARS。
3. 打开 manage-mars-windows.cmd，选择 7（Slow model profile）。
4. 双击 MARS-Windows.cmd，先新建对话测试“列出当前项目的研究记录”，再测试一个已有模型的 2 epoch 仿真。

慢模型配置将请求超时至少设为 600 秒；主控输出上限降为 2048 Token，关闭可选思考。GLM-5.3 的强制思考设置保留，研究和编码阶段的思考设置不变。连接测试超时至少为 120 秒，输出上限为 128 Token。阶段级重试最多 1 次，主控仍不盲目重试超时请求。

模型名、接口、密钥、项目和对话保持不变，原配置保存在 local/model-profiles/ 下。恢复：先停止 MARS，再打开管理菜单选择 8（Restore model settings）。若应用后你又修改过模型配置，恢复会保留当前配置并要求从备份手动合并。

## 首次排查顺序

一次只提交一个测试任务。先检查短文本回复，再检查实际工具调用，最后启动已有模型仿真。
如果短文本都不能在配置时间内返回，应让模型服务维护者检查排队时长、首 Token 耗时、生成速度和服务端超时。MARS 的超时设置不能改变网关自身的截止时间，也不能提升模型的方案质量。

长时间没有收到任何返回与持续返回但生成缓慢是不同情况。不要连续点击重试来叠加排队请求；先确认原任务和服务请求是否仍在处理。模型失败的记录、任务和实际工具结果保留在原项目中。

## 公司千问与 Gemma 配置

也可以直接在研究对话输入区的“对话模型”下拉框选择“配置自定义模型”，保存多套显示名称、真实模型 ID、接口、密钥、部署容量和兼容配置。保存一次后，所有项目都能选择；不用在每个项目重新配置。下拉选择会作为之后新对话的默认值，旧对话保留自己的选择。正在处理消息时不能切换。

这里切换的是**对话主控模型**。已创建的研究任务和后台编码 Agent 保留原配置，不随对话选择一起切换。密钥另存在本机 `local/model_profile_secrets.json`，API 和页面只显示是否已配置，编辑时密钥留空表示保留。`local/model_profiles.json` 保存模型连接列表；两个文件都不会进入 GitHub 核心代码包。替换核心包时保留整个 `local/` 目录。

这两种配置针对公司提供的 OpenAI 兼容接口。先在 MARS 设置中填写接口、密钥和公司服务要求的**真实模型 ID**。你提供的“千问 3.8 27b”和“gemma-4-35b-it”可以是内部型号或别名；MARS 不替换名字，也不拿公开型号白名单拦截它们。

停止 MARS 后打开管理菜单：

| 菜单 | 部署容量 | 主控工作上下文 | 主控工具指令 |
| --- | ---: | ---: | --- |
| 9：Company Qwen | 200000 Token | 12000 Token | 直接使用明确的文本工具指令，关闭默认长思考 |
| 10：Company Gemma | 160000 Token | 12000 Token | 直接使用明确的文本工具指令，兼容单 user 消息模板 |

容量来自你告知的公司部署参数，并非公开型号规格。接口实际设置的容量若更小，需要相应调小 `configs/agents.yaml` 中 `model.context_window`。更换模型后，重新选择与它对应的配置。菜单不会更改模型 ID、接口或密钥。

大容量是上限，不是每次都填满的目标。主控仅装入当前任务、必要约束和近期真实回执，仍为输出及安全余量预留空间；研究与编码不会被统一截到 12000 Token。任务所需信息超过主控工作上下文时，MARS 保留原文件及引用，按需再读。

同一模型路由的 Agent 使用 SSE，保留已收到的实际进度；连接中断时不会把半截 JSON 当成已完成指令。主控直接走文本工具协议，省去一次失败的原生 tools 请求。明确的工具名与参数经过正常准入后执行，模型仅说“下一步会运行”不能充当执行回执。主控兼容仅接受 user 消息的模板，其他调用把多条 system 消息归并到开头，保留所有约束与工具回执绑定。

Gemma 配置不发送非标准 `thinking`、`reasoning_effort`、`response_format` 等扩展。千问配置显式选择官方 Qwen3.8 指令模式：`chat_template_kwargs.enable_thinking=false`、`preserve_thinking=false`。官方模板默认长思考，单将 MARS 的思考标志关闭不会改变模型服务默认值。该配置只在你选择菜单 9 后启用，不根据内部模型名猜测。公司网关若自行剥掉该参数，需服务维护者在部署端确认关闭长思考；网关使用其他协议时可改用菜单 7 的通用兼容配置。

恢复配置仍用菜单 8。恢复前后保留项目、对话、依赖和 `.env.local`。新配置只影响之后的新调用，已完成记录保持原样。

这些适配已验证本地请求构造、SSE 分段聚合、真实连接失败和配置恢复，无法代替公司模型的现场验收。公司模型若无法产生一条明确指令，系统应保留请求并显示具体失败原因；不能宣称不存在或未执行的结果。

部署工具解析与聊天模板有关，参考 [Qwen 官方 Function Calling 文档](https://qwen.readthedocs.io/en/stable/framework/function_call.html)、[Qwen3.8-27B 官方模型卡](https://huggingface.co/Qwen/Qwen3.8-27B) 与 [Gemma 官方 Function Calling 文档](https://ai.google.dev/gemma/docs/capabilities/text/function-calling-gemma4)。这些资料用于协议设计，并不证明公司内部别名对应某个公开版本。
